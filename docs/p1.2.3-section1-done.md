## What Was Delivered

Phase 1.2.3 Section 1 delivers the vector storage module for the hybrid RAG system. `src/storage/chroma_store.py` was created with two classes: `TraceAlchemyEmbeddingFunction`, a custom ChromaDB-compatible embedding function that calls the local llama-server `/v1/embeddings` endpoint; and `ChromaStore`, a persistent ChromaDB wrapper providing document CRUD, batch ingestion, semantic search, ticker-specific filtering, collection lifecycle management, and a heartbeat health check. The module reads its endpoint and collection defaults from `configs/storage.yaml`, uses cosine similarity for finance-domain semantic matching, and ships with unit tests that mock the embedding network layer so CI runs without a live llama-server.

## CRUD Methods Delivered

**Single Document Operations:**
- `add_document(document_id, text, metadata=None, ticker=None, source=None, date=None)` — Add one document with optional metadata enrichment and ticker uppercasing.
- `get_document(document_id)` — Retrieve a single document by ID; returns dict or `None`.
- `delete_document(document_id)` — Remove a single document by ID.

**Batch Operations:**
- `add_documents_batch(ids, texts, metadatas=None)` — Add multiple documents in one call; more efficient for ingestion pipelines.

**Search Operations:**
- `search(query, n_results=5, filter_dict=None)` — Semantic search with optional metadata filters; returns formatted list of result dicts.
- `search_by_ticker(query, ticker, n_results=5)` — Convenience wrapper that searches within a single ticker’s documents.
- `get_ticker_documents(ticker, source=None, limit=20)` — List all documents for a ticker, optionally filtered by source.

**Collection Management:**
- `count()` — Return the total number of documents in the collection.
- `reset_collection()` — Drop and recreate the collection (useful for testing and re-ingestion).
- `heartbeat()` — Check ChromaDB responsiveness; returns boolean.

**Embedding Layer:**
- `TraceAlchemyEmbeddingFunction(endpoint, model, batch_size, timeout)` — Custom ChromaDB `EmbeddingFunction` implementation that POSTs to the llama-server `/v1/embeddings` endpoint, parses the `{"data": [{"embedding": [...]}, ...]}` response, and handles batching automatically.

## Execution Workflow Notes

- **Initialization is self-contained:** `ChromaStore.__init__` auto-creates the `data/chroma` directory if missing via `mkdir(parents=True, exist_ok=True)`.
- **Embedding function lifecycle:** `TraceAlchemyEmbeddingFunction` opens an `httpx.Client` on init and closes it in `__del__`. In production, avoid creating many short-lived `ChromaStore` instances to prevent connection churn.
- **Batch size safety:** Default `batch_size=10` prevents oversized embedding requests. The loop in `__call__` processes arbitrary-length input lists safely.
- **Ticker normalization:** All ticker inputs are uppercased automatically (e.g., `"nvda"` → `"NVDA"`) before adding to metadata or building query filters, ensuring consistent filtering.
- **Cosine similarity:** Collection metadata explicitly sets `hnsw:space` to `cosine`. Search results expose `distance` where smaller values indicate higher relevance.
- **No live server required for tests:** The test suite patches `httpx.Client.post` to return synthetic embedding vectors, covering all `ChromaStore` code paths without a running llama-server.

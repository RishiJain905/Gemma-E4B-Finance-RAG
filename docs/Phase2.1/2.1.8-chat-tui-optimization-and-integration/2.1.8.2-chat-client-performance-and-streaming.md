# 2.1.8.2 — Chat Client Performance & Streaming

## Objective

Make `scripts/chat.py` feel fast: reuse a single HTTP connection, stream tokens
as they generate (so first output appears immediately), and show responsiveness
cues (elapsed timer / spinner) so long generations don't feel frozen.

## Why This Matters

Two client-side issues make the TUI feel slow even when the server is fine:
(1) `chat.py` opens a **new connection per message** (`httpx.post(...)` each
time) — no keep-alive; (2) it **waits for the full answer** before printing
anything, so a 10 s generation looks like a 10 s hang. Streaming + connection
reuse fix the *perceived* speed dramatically.

## Step 1: Persistent HTTP client

Replace the per-call `httpx.post(...)` with a single module/session
`httpx.Client(base_url=..., timeout=...)` reused for every request (and a
matching one for `/refresh`, `/health`). Reuse keep-alive connections to both
the middleware and any direct calls.

**Files to modify:** `scripts/chat.py`.

## Step 2: Streaming answers

Depends on the middleware supporting streaming (potential-ideas Tier 2 #6;
`QueryRequest.stream` is already reserved). This task includes wiring it
end-to-end:

- **Middleware:** add a streaming branch to `/query` (or a `/query/stream`
  SSE endpoint) that proxies llama-server's token stream; emit the final
  metadata (citations, grounding, timings) as a terminal event.
- **chat.py:** when streaming, print tokens as they arrive; then print the
  metadata line once the stream closes.

```python
# chat.py (sketch)
with client.stream("POST", "/query/stream", json=payload) as r:
    for chunk in r.iter_lines():
        token = parse_sse(chunk)
        if token: print(token, end="", flush=True)
```

Fall back to the existing non-streaming path if the server doesn't offer the
stream endpoint (older middleware) — detect once and remember.

**Files to modify:** `src/middleware/app.py`, `scripts/chat.py`,
`src/middleware/config.py` (`enable_streaming`).

## Step 3: Responsiveness cues (non-streaming fallback)

When not streaming, show a lightweight elapsed-time spinner on a background
thread while awaiting the response, cleared when the answer prints. Keeps the
TUI from looking hung during generation.

**Files to modify:** `scripts/chat.py`.

## Step 4: Tunables

- `--timeout`, `--no-stream` CLI flags.
- Print the server's `timings` breakdown under the answer when present (from
  2.1.8.1) behind a `/verbose` toggle, so you can see model-vs-retrieval split
  right in the TUI.

## Testing

Create `tests/test_chat_client.py` (no real server — patch httpx):
- `test_uses_persistent_client` — multiple sends reuse one client instance.
- `test_streaming_prints_incrementally` — fed a fake SSE token stream, tokens
  are emitted before the final metadata (capture stdout).
- `test_stream_fallback` — server without the stream endpoint → falls back to
  non-streaming, still prints an answer.
- `test_spinner_cleared` — non-stream path prints the answer and leaves no
  spinner artifacts.
- `test_verbose_shows_timings` — `/verbose` on prints the `timings` block.
- Keep these unit-level by mocking the HTTP layer; mark any real-server check
  `integration`.

# 2.1.3.1 — Structure & Sentence-Aware Chunker

## Objective

Replace the fixed ~1000-char sliding window in `ChromaStore._chunk_text` with a
**structure-aware** chunker that splits on document structure (filing sections,
headings, paragraphs) and respects **sentence boundaries**, producing
semantically coherent chunks.

## Why This Matters

Retrieval can never be better than the chunks it searches. Fixed-character
windows cut mid-sentence and mix unrelated topics, which dilutes embeddings and
hurts both vector and cross-encoder relevance. Coherent, section-aligned chunks
improve every downstream stage.

## Step 1: Add a chunking module

Create `src/storage/chunking.py` with a `chunk_document(text, *, source, max_chars, overlap)`:

1. **Structural split first** — for SEC filings, split on common section
   markers ("Item 1A. Risk Factors", "Management's Discussion", etc.); for
   other sources, split on blank-line paragraphs / markdown headings.
2. **Sentence-aware packing** — within each section, pack sentences (regex or
   `nltk`/`blingfire` if available; fall back to a punctuation splitter) into
   chunks up to `max_chars`, never breaking a sentence.
3. **Overlap by sentences** — carry the last 1–2 sentences into the next chunk
   instead of a raw char overlap.
4. Emit chunk dicts with `text` + structural metadata (`section`, `chunk_index`,
   `chunk_count`).

```python
# src/storage/chunking.py (sketch)
def chunk_document(text, *, source=None, max_chars=1000, overlap_sentences=1):
    sections = _split_sections(text, source)
    chunks = []
    for sec_name, sec_text in sections:
        for body in _pack_sentences(sec_text, max_chars, overlap_sentences):
            chunks.append({"text": body, "section": sec_name})
    for i, c in enumerate(chunks):
        c["chunk_index"] = i; c["chunk_count"] = len(chunks)
    return chunks
```

**Files to create:** `src/storage/chunking.py`
**Files to modify:** `requirements.txt` (optional `blingfire`/`nltk`).

## Step 2: Use it in ChromaStore

Refactor `ChromaStore.add_document` to call `chunk_document` and store each
chunk with its section metadata. Keep the existing id scheme (`{id}#{i}`) and
the single-entry behavior for short docs. Preserve `parent_id`.

**Files to modify:** `src/storage/chroma_store.py`.

## Step 3: Make it configurable + backward-safe

- Config in `storage.yaml`: `chunk_strategy: structural|fixed`, `max_chars`,
  `overlap_sentences`. Default to `structural`, but keep `fixed` selectable to
  reproduce old behavior.
- The old `_chunk_text` stays available (used by `fixed` strategy / tests).

## Testing

Create `tests/test_chunking.py` (no network — pure function):

- `test_no_midsentence_cuts` — every chunk ends on sentence punctuation

- `test_section_split_sec_filing` — a fixture with "Item 1A." / "Item 7."

- `test_sentence_overlap` — consecutive chunks share the trailing sentence(s).
- `test_chunk_metadata` — `chunk_index`/`chunk_count`/`section` set correctly.
- `test_fixed_strategy_matches_legacy` — `fixed` reproduces old splitting.

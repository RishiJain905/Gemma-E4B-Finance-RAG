# 2.1.4.3 — Read-Only Data Tools

## Objective

Expose the rest of the existing read capabilities as model-callable tools so
the model can pull exactly the data it needs on demand:
`get_fundamentals`, `search_documents`, `get_macro_snapshot`, `get_sentiment`,
`get_guidance`, and `check_freshness`.

## Why This Matters

`query_facts` (2.1.4.2) handles ranking/aggregation; these tools cover targeted
lookups, qualitative context, macro/sentiment/guidance, and freshness-awareness.
Together they let the model assemble a complete, grounded answer instead of
relying solely on the single up-front retrieval pass.

## Step 1: Implement the tools

Add to `src/middleware/tools/data_tools.py`. Each backs onto an existing
store method or endpoint handler (reuse, don't duplicate logic):

| Tool | Params | Backs onto |
|------|--------|-----------|
| `get_fundamentals` | `ticker`, `metrics[]` | `Store.get_fundamentals_batch` |
| `search_documents` | `query`, `ticker?`, `n_results?` | `Store.search` |
| `get_macro_snapshot` | — | `Store.get_fundamentals_batch("MACRO", …)` |
| `get_sentiment` | `ticker`, `days?` | `GDELTIngestor.get_sentiment_summary` |
| `get_guidance` | `ticker` | `EarningsTranscriptIngestor.get_latest_guidance` |
| `check_freshness` | `ticker` | `Store.get_freshness_report` |

```python
def get_fundamentals_handler(store, ticker, metrics=None):
    return {"ticker": ticker.upper(),
            "fundamentals": store.get_fundamentals_batch(ticker.upper(), metrics)}

def search_documents_handler(store, query, ticker=None, n_results=5):
    res = store.search(query=query, n_results=n_results, ticker=ticker)
    return {"documents": [{"id": d["id"], "text": d["document"][:1500],
                           "metadata": d.get("metadata", {})} for d in res["documents"]]}
```

All registered `write=False`.

**Files to modify:** `src/middleware/tools/data_tools.py`,
`src/middleware/tools/__init__.py` (register).

## Step 2: Keep results model-friendly

- Truncate long document text in `search_documents` (e.g. 1500 chars/chunk) so
  tool results don't blow the context window.
- Return compact JSON with stable keys; include units/periods for facts so the
  model cites correctly.
- On a backend error (e.g. sentiment when GDELT empty), return
  `{"error": "...", "ticker": ...}` rather than raising — the model can adapt.

## Step 3: Avoid duplication with the endpoints

Refactor the existing endpoint bodies (`/sentiment`, `/guidance`,
`/macro/snapshot`) to call the same underlying functions the tools use, so
there's a single source of truth.

**Files to modify:** `src/middleware/app.py` (share helpers with tools).

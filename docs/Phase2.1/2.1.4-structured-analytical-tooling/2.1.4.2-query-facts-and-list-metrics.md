# 2.1.4.2 — `query_facts` & `list_metrics` (the analytical core)

## Objective

Implement the two tools that unlock analytical questions: **`query_facts`**
(rank/filter/aggregate over the `fundamentals` table) and **`list_metrics`**
(introspection of available tickers/metrics so the model uses valid arguments).
These directly fix questions like *"which stock has the lowest forward P/E?"*

## Why This Matters

Vector search can't sort or aggregate. `query_facts` lets the model ask the
database the right structured question and reason over the truthful result;
`list_metrics` grounds it so it never invents a metric name.

## Step 1: `list_metrics` / `describe_schema`

Add `src/middleware/tools/data_tools.py` with a `list_metrics` tool:
- Returns the distinct `metric` values and the set of tickers present in
  `fundamentals` (excluding synthetic `MACRO`/`TEST` unless asked).
- Backs onto a new `SQLiteStore.list_metrics()` / `list_tickers()` helper.

```python
# handler sketch
def list_metrics_handler(store, ticker=None):
    return {"metrics": store.sqlite.list_metrics(ticker),
            "tickers": store.sqlite.list_tickers()}
```

## Step 2: `query_facts`

Add a `query_facts` tool that performs safe structured queries over
`fundamentals`. Parameters (JSON schema):
- `metric` (required, validated against `list_metrics`)
- `tickers` (optional list filter)
- `order` (`asc`|`desc`), `limit` (default 10)
- `op` + `value` (optional threshold, e.g. `op="lt", value=20`)
- `latest_only` (bool, default true — use each ticker's most recent period)

Implement as **parameterized SQL** (not free-form text-to-SQL, for safety):

```python
def query_facts_handler(store, metric, tickers=None, order="asc",
                        limit=10, op=None, value=None, latest_only=True):
    rows = store.sqlite.query_metric(metric, tickers=tickers, order=order,
                                     limit=limit, op=op, value=value,
                                     latest_only=latest_only,
                                     exclude=DATA_SANITY_EXCLUDE)
    return {"metric": metric, "results": rows}
```

Add `SQLiteStore.query_metric(...)` building a parameterized
`SELECT ticker, value, period FROM fundamentals WHERE metric=? ...
ORDER BY value {asc|desc} LIMIT ?` with the latest-period correlation already
used by `get_fundamentals_batch`.

**Files to create:** `src/middleware/tools/data_tools.py`
**Files to modify:** `src/storage/sqlite_store.py` (`list_metrics`,
`list_tickers`, `query_metric`).

## Step 3: Data-sanity filtering

`query_metric` must support an exclude set / sanity rules so "lowest forward
P/E" doesn't return junk:
- Exclude non-equity symbols (ETFs/bonds: `TLT`, `GLD`, `SPY`, `QQQ`, …) for
  equity-only metrics like P/E.
- Drop implausible values (e.g. negative or absurd `forward_pe`) via an
  optional sane-range filter per metric.
- Make the exclusion list/config-driven (`configs/analytics.yaml`).

**Files to create:** `configs/analytics.yaml` (excluded symbols, metric ranges).

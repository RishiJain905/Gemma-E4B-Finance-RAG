# 2.1.5.2 — Projection Tool, Intent & Prompt Tuning

## Objective

Make the ingested estimates (2.1.5.1) usable: a `get_estimates` /
`get_price_targets` tool, a new `projection`/`outlook` **intent**, and prompt
tuning so the model answers "what to expect" by **reasoning over sourced
consensus** — never by fabricating its own numbers.

## Why This Matters

Data alone isn't enough; the model must (a) know to reach for it on
forward-looking questions, and (b) frame the answer as analyst consensus +
reasoning with caveats. This is the truthfulness guardrail for projections.

## Step 1: Estimates tools

Add to `src/middleware/tools/data_tools.py` (read-only, registered via 2.1.4.1):
- `get_estimates(ticker, horizon?)` → forward `estimate_revenue`/`estimate_eps`
  (+ growth vs. last realized period if available).
- `get_price_targets(ticker)` → mean/high/low + `num_analysts` +
  `recommendation_mean`.

Back onto `query_facts`/`get_fundamentals` filtered to `source_type="estimates"`
and `*E` periods.

```python
def get_price_targets_handler(store, ticker):
    pt = store.get_fundamentals_batch(ticker.upper(),
        ["price_target_mean","price_target_high","price_target_low",
         "num_analysts","recommendation_mean"])
    return {"ticker": ticker.upper(), "price_targets": pt}
```

**Files to modify:** `src/middleware/tools/data_tools.py`.

## Step 2: `projection` intent

Extend `src/middleware/intent_parser.py`:
- Add a `projection` question type with patterns: `\bexpect(ed|ations)?\b`,
  `\bforecast\b`, `\bprice target\b`, `\bnext (quarter|year)\b`, `\bguidance\b`,
  `\bprojection\b`, `\bwill .* (grow|reach|hit)\b`, `\bestimate[ds]?\b`.
- Place it in `_TYPE_PRIORITY` so it wins over generic `fact_lookup` when these
  cues appear.
- Map metric cue "price target" → estimate metrics.

**Files to modify:** `src/middleware/intent_parser.py`,
`tests/test_intent_parser.py` (extend; it's at 100% coverage).

## Step 3: Prompt tuning for projections

In `src/middleware/prompt_augmenter.py`, when `intent.question_type ==
"projection"`:
- Inject the estimates/price-target context with explicit labels ("Analyst
  consensus (N analysts): revenue $X, EPS $Y; price target mean $Z, range
  $lo–$hi").
- Use a projection-specific instruction: *report the consensus and a reasoned
  read of it; clearly separate sourced figures from interpretation; include a
  "these are analyst estimates, not guarantees / not financial advice" caveat;
  never state your own invented target.*
- Optionally route projection queries to the model's `analysis` task params from
  `model.yaml` (temperature/max_tokens).

**Files to modify:** `src/middleware/prompt_augmenter.py`,
`src/middleware/app.py` (intent-aware system prompt / task params).

## Step 4: Guardrail

Add a post-generation check (lightweight): if the answer contains a specific
price target or estimate figure that is **not** present in the provided
estimates context, flag/strip it or append a caveat. Keep simple (regex for
`$` figures cross-checked against context); full citation verification is
Tier 3 #7.

## Testing

  "what should I expect next quarter" → `projection`.

- `test_no_fabricated_target_guard` — answer with an unsupported `$` figure is

# 2.1.1.1 — Golden Dataset & Evaluation Runner

## Objective

Build the foundation of the evaluation harness: a curated **golden dataset** of
financial questions with expected answers/sources, and a **runner** that drives
the full query pipeline (or the live `/query` endpoint) over that dataset and
captures the answer, retrieved facts/documents, and timing for each case.

## Why This Matters

Every other Phase 2.1 feature (re-ranking, tools, projections, answer policy)
claims to improve answer quality. Without a repeatable measurement you're
guessing. The golden set + runner is the scoreboard — it turns "this feels
better" into "faithfulness went 0.71 → 0.86, retrieval hit-rate 0.6 → 0.9".

## Step 1: Define the golden dataset format

Create `eval/golden/finance_qa.jsonl` — one JSON object per line:

```json
{"id": "rev-nvda-001",
 "question": "What was NVDA's latest revenue?",
 "expected_ticker": "NVDA",
 "expected_intent": "fact_lookup",
 "must_mention": ["revenue"],
 "expected_sources": ["yfinance", "sec"],
 "category": "fact_lookup"}
{"id": "cmp-pe-001",
 "question": "Which tracked stock has the lowest forward P/E?",
 "expected_ticker": null,
 "expected_intent": "comparison",
 "must_mention": [],
 "category": "analytical",
 "notes": "Currently unanswerable without the 2.1.4 tool suite — tracks regression/uplift."}
```

Seed **~30–50 cases** spanning every intent (`fact_lookup`, `comparison`,
`trend`, `explanation`, `sentiment`, `news`, `risk`, `general`) plus known
hard cases (analytical aggregation, untracked ticker, projection).

**Files to create:**
- `eval/golden/finance_qa.jsonl`
- `eval/README.md` (how to add cases, how to run)

## Step 2: Build the runner

Create `eval/run_eval.py` that, for each case:
1. Calls the pipeline. Prefer the **live middleware** (`POST /query`) so it
   measures the real system; fall back to importing the pipeline directly.
2. Records: `answer`, `detected_ticker`, `detected_intent`, `facts_used`,
   `documents_used`, the retrieved doc ids, `latency_ms`, `model_available`.
3. Writes a run artifact to `eval/runs/<timestamp>.jsonl` (raw) plus a summary.

```python
# eval/run_eval.py (sketch)
import json, time, httpx
from pathlib import Path

GOLDEN = Path("eval/golden/finance_qa.jsonl")
QUERY_URL = "http://127.0.0.1:8000/query"

def run_case(case: dict) -> dict:
    t0 = time.time()
    resp = httpx.post(QUERY_URL, json={"question": case["question"], "refresh": False}, timeout=240)
    data = resp.json()
    return {
        "id": case["id"],
        "question": case["question"],
        "answer": data.get("answer", ""),
        "detected_ticker": data.get("detected_ticker"),
        "detected_intent": data.get("detected_intent"),
        "facts_used": data.get("facts_used"),
        "documents_used": data.get("documents_used"),
        "model_available": data.get("model_available"),
        "latency_ms": data.get("latency_ms"),
        "case": case,
    }

def main():
    cases = [json.loads(l) for l in GOLDEN.read_text().splitlines() if l.strip()]
    results = [run_case(c) for c in cases]
    out = Path(f"eval/runs/{int(time.time())}.jsonl")
    out.parent.mkdir(parents=True, exist_ok=True)
    out.write_text("\n".join(json.dumps(r) for r in results))
    print(f"Wrote {len(results)} results -> {out}")
```

**Files to create:**
- `eval/run_eval.py`
- `eval/runs/` (gitignored)

## Step 3: Gitignore run artifacts

Add to `.gitignore`:
```gitignore
eval/runs/
```
The golden set IS committed; per-run outputs are not.

## Testing

Create `tests/test_eval_harness.py`:
- `test_golden_dataset_valid` — every line in `finance_qa.jsonl` parses, has
  required keys (`id`, `question`, `category`), and ids are unique.
- `test_runner_shapes_result` (mark `integration`/`network`, skip if `:8000`
  down) — running one case returns a dict with all expected keys.
- `test_runner_offline_fallback` — with the endpoint patched/mocked, the runner
  still produces a well-formed result row.

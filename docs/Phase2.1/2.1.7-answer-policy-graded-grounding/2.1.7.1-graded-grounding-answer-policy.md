# 2.1.7.1 — Graded Grounding Answer Policy

## Objective

Replace the current strict "answer only from context, else refuse" behavior
with a **graded grounding policy**: answer fully from data when present,
summarize-and-flag when partial, and fall back to clearly-labeled general
knowledge (with a caveat) when absent — while never fabricating specific
figures.

## Why This Matters

Today the system refuses too readily ("I don't have enough data") even when it
has partial context or could give useful background. That makes it feel broken.
This task makes it *helpful by default* while keeping it *honest*, which is the
behavior change you asked for. It also depends on the eval harness (2.1.1) to
prove helpfulness rose without faithfulness falling.

## Step 1: Define the policy

Four response modes the model must choose between, by how much grounded context
it received:

1. **Grounded** — sufficient facts/docs → answer and cite `[Source: …]`.
2. **Partial** — some relevant data → answer what's supported, explicitly note
   what's missing ("I have NVDA revenue but no margin data").
3. **General fallback** — no relevant data → may use general/background
   knowledge, clearly prefixed ("Not from your data — general knowledge:")
   plus a "verify against a primary source" caveat.
4. **Refuse only** for genuinely unknowable/unsafe asks.

Hard rule across all modes: **never invent specific numbers** (prices, P/E,
targets, revenue). Specific figures must come from context/tools.

Document the policy in `docs/ARCHITECTURE.md` (a "Answer policy" section).

## Step 2: Rewrite the system prompt

In `src/middleware/app.py::_call_model`, replace the strict system prompt with
the graded policy. Make it **intent-aware** — pass the detected intent and a
"grounding level" hint computed from `facts_used`/`documents_used`:

```python
def _grounding_level(retrieval):
    n = len(retrieval.get("facts", [])) + len(retrieval.get("documents", []))
    return "grounded" if n >= 3 else "partial" if n >= 1 else "none"
```

The system prompt instructs the model which mode to use for that level, with
the never-fabricate rule and the labeling/caveat requirements.

**Files to modify:** `src/middleware/app.py`,
`src/middleware/prompt_augmenter.py` (thread intent + grounding level).

## Step 3: Make it configurable

- `config.answer_policy: graded|strict` (default `graded`; `strict` reproduces
  current behavior for comparison/rollback).
- `config.allow_general_fallback: bool` — lets cautious deployments disable the
  general-knowledge mode while keeping partial answers.

**Files to modify:** `src/middleware/config.py`, `configs/middleware.yaml`.

## Step 4: Response signaling

Add `grounding` to the `/query` response metadata
(`grounded|partial|general|refused`) so the client (and the eval harness) can
see which mode produced the answer. Surface it in `scripts/chat.py`.

**Files to modify:** `src/middleware/models.py`, `src/middleware/app.py`,
`scripts/chat.py`.

## Step 5: Evaluate (uses 2.1.1)

This is the feature most at risk of trading faithfulness for helpfulness — so
gate it on the harness. Record in
`docs/Phase2.1/2.1.7-answer-policy-graded-grounding/RESULTS.md`:
- `refusal_rate` should **drop** materially.
- `faithfulness` must **not** drop (the never-fabricate rule + labeling keeps
  general-knowledge answers honest).
- Add golden cases for partial-data and untracked-entity questions asserting a
  helpful (non-refusal) yet caveated answer.

## Testing

Create `tests/test_answer_policy.py`:
- `test_grounding_level` — facts/docs counts map to grounded/partial/none.
- `test_strict_mode_unchanged` — `answer_policy=strict` reproduces the old
  prompt (regression guard).
- `test_graded_prompt_includes_mode` — built system prompt reflects the
  computed grounding level and the never-fabricate rule.
- `test_general_fallback_labeled` (mock model) — none-level answer is prefixed
  "Not from your data" + caveat; `allow_general_fallback=False` suppresses it.
- `test_response_reports_grounding` — `/query` metadata includes `grounding`.
- `test_no_fabricated_numbers_rule_present` — prompt contains the explicit
  numeric-fabrication prohibition.

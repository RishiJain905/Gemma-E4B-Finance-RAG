# 2.1.6.2 — On-Demand "Fetch-on-Miss" Ingestion

## Objective

When a query resolves to a **valid but untracked** ticker (e.g. BB), fetch its
data live and answer — instead of refusing — without permanently bloating the
watchlist. This scales the universe to any valid symbol on demand.

## Why This Matters

2.1.6.1 makes the system *recognize* more tickers; this makes it *have data* for
them. Pre-ingesting thousands of tickers is wasteful; fetching on first request
is the scalable pattern and pairs naturally with the `refresh_data` tool (2.1.4.4).

## Step 1: Detect the "tracked vs. untracked" case

In the `/query` freshness step (`_evaluate_and_refresh`) and/or the retriever:
- After resolving a ticker, check whether the store has *any* data for it
  (`get_freshness_report` overall == `never_fetched` and no facts/docs).
- If untracked but valid (resolver confidence high), mark it a fetch-on-miss
  candidate.

**Files to modify:** `src/middleware/app.py`.

## Step 2: Bounded on-demand fetch

Add `src/middleware/on_demand.py::fetch_ticker_on_miss(store, ticker)`:
- Fetch the **cheap, no-key** essentials only: yfinance fundamentals + news
  (reuse `YFinanceIngestor._fetch_ticker` / `_ingest_ticker_*`). Skip heavy
  sources (SEC deep parse, transcripts) on the hot path.
- Time-box it (e.g. ≤ ~10s) and run at most once per query; on failure, return
  cleanly so the answer can say "couldn't fetch live data for X right now".
- Optionally persist so the ticker becomes tracked (add to a dynamic
  `data/tracked_dynamic.json` rather than editing `watchlist.yaml`).

```python
def fetch_ticker_on_miss(store, ticker):
    from src.ingestion.yfinance_ingestor import YFinanceIngestor
    ing = YFinanceIngestor(store=store)
    t = ing._fetch_ticker(ticker)
    if t is None: return {"fetched": False, "ticker": ticker}
    ing._ingest_ticker_fundamentals(ticker, t)
    return {"fetched": True, "ticker": ticker}
```

**Files to create:** `src/middleware/on_demand.py`
**Files to modify:** `.gitignore` (`data/tracked_dynamic.json`).

## Step 3: Config + guardrails

- `config.enable_fetch_on_miss` (default true), `fetch_on_miss_timeout_s`,
  `fetch_on_miss_per_query` (=1).
- Respect upstream rate limits; never trigger SEC/GDELT/transcript scraping on
  the hot path (those stay scheduler/`refresh_data` territory).
- The model's `refresh_data` tool (2.1.4.4) remains the explicit path; this is
  the automatic, lightweight one.

**Files to modify:** `src/middleware/config.py`, `configs/middleware.yaml`.

## Step 4: Reflect in the answer

When a fetch-on-miss happened, include it in the `/query` freshness metadata
(`fetched_on_miss: ["BB"]`) so the UI/chat can note "fetched live data for BB".

**Files to modify:** `src/middleware/models.py` (freshness block), `app.py`.

## Testing

Create `tests/test_fetch_on_miss.py`:

- `test_invalid_ticker_no_fetch` — resolver returns None → no fetch, graceful.
- `test_fetch_failure_graceful` — yfinance returns None → query still answers

- `test_disabled_flag` — `enable_fetch_on_miss=False` → never fetches.
- `test_only_cheap_sources` — assert SEC/GDELT/transcript ingestors are NOT
  invoked on the hot path.

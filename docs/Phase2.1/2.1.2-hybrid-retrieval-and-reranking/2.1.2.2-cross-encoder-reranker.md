# 2.1.2.2 — Cross-Encoder Re-Ranker

## Objective

Add a **cross-encoder re-ranker** that re-scores the top fused candidates from
2.1.2.1 by jointly reading (query, document) pairs, then keeps the best N for
the prompt. This is usually the single biggest answer-quality jump in a RAG.

## Why This Matters

Bi-encoder vector search and BM25 score the query and doc *separately*. A
cross-encoder reads them *together*, so it judges true relevance far better.
Retrieve broadly (e.g. top 30 fused), re-rank, keep top 5 → the model sees the
genuinely most relevant context.

## Step 1: Re-ranker module

Add `src/middleware/reranker.py` with a `Reranker` wrapping a cross-encoder.

- Default model: `cross-encoder/ms-marco-MiniLM-L-6-v2` (small, CPU-friendly)
  via `sentence-transformers`. Make the model id configurable.
- `rerank(query, docs, top_n)` → returns docs sorted by cross-encoder score.
- Lazy-load the model on first use; cache the instance.

```python
# src/middleware/reranker.py (sketch)
from sentence_transformers import CrossEncoder

class Reranker:
    def __init__(self, model_id="cross-encoder/ms-marco-MiniLM-L-6-v2"):
        self.model_id = model_id; self._model = None

    @property
    def model(self):
        if self._model is None:
            self._model = CrossEncoder(self.model_id)
        return self._model

    def rerank(self, query, docs, top_n=5):
        if not docs: return docs
        pairs = [(query, d["document"]) for d in docs]
        scores = self.model.predict(pairs)
        ranked = sorted(zip(docs, scores), key=lambda x: -x[1])
        for d, s in ranked: d["rerank_score"] = float(s)
        return [d for d, _ in ranked[:top_n]]
```

**Files to create:** `src/middleware/reranker.py`
**Files to modify:** `requirements.txt` (`sentence-transformers`),
`src/middleware/config.py` (`enable_reranker`, `reranker_model`,
`rerank_candidates`, `rerank_top_n`).

## Step 2: Wire into the retriever

In `retriever.py`: retrieve `rerank_candidates` (e.g. 30) via fused
vector+BM25, run `Reranker.rerank(query, candidates, rerank_top_n)`, pass the
result to the prompt augmenter. Guard behind `config.enable_reranker`.

## Step 3: Performance + fallback

- Re-ranking 30 short candidates on CPU is ~tens of ms; log the added latency.
- If the model can't load (offline first run / download failure), **fall back**
  to the fused order and log a warning — never fail the query.
- Document the one-time model download in the README/CONTRIBUTING.

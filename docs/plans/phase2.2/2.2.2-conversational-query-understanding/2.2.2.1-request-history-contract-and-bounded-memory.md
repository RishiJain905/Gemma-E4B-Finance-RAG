# 2.2.2.1 — Request History Contract & Bounded Client Memory

## Objective

Add an explicit, bounded conversation-history contract to `/query` while
keeping the middleware stateless. `scripts/chat.py` owns each session's recent
turns and sends them with the current raw question; the server validates and
uses that history without persisting it or leaking it between callers.

## Why This Matters

`ChatSession` is currently only an HTTP connection wrapper. Every request
contains the current question, so a follow-up such as “what about AMD in the
same period?” loses the ticker, metric, and timeframe established one turn
earlier. Server-owned memory would solve that symptom by adding a new database,
retention policy, cleanup path, and concurrency boundary. Client-owned bounded
history provides conversation semantics with a much smaller operational
surface.

## Step 1: Define the additive API contract

Add `ChatTurn` to `src/middleware/models.py`:

- `role: Literal["user", "assistant"]`;
- `content: str` with nonblank validation;
- optional `turn_id: str` for tracing only;
- optional structured `context` containing resolved tickers, metrics,
  timeframe, and answer grounding from a prior response.

Extend `QueryRequest` with:

- `history: list[ChatTurn] = Field(default_factory=list)`;
- optional `session_id` limited to a safe opaque identifier;
- a 16,000-character current-question limit;
- no server-side lookup semantics for `session_id`.

Extend `QueryResponse` with optional `conversation` metadata:

```json
{
  "history_turns_received": 4,
  "history_turns_used": 4,
  "history_truncated": false,
  "topic_reset": false
}
```

All fields are additive. Requests without `history` must retain the current
single-turn behavior.

**Files to modify:**
- `src/middleware/models.py`
- `tests/test_middleware.py`

## Step 2: Validate one shared conversation budget

Create `src/middleware/conversation.py` with a dependency-free
`select_history(turns, *, max_turns, max_chars)` helper.

Default limits:

- at most eight recent turns;
- at most 8,000 history characters;
- at most 16,000 characters in the current question;
- current question is outside the history budget and is never silently cut;
- keep complete turns only, newest first until the budget is filled, then
  restore chronological order;
- reject malformed roles/content with a clear 422 response;
- record dropped-turn counts in response metadata.

Do not summarize history in this task. A generated summary would add a model
call and could silently change finance entities or numbers. Structured context
from prior responses is retained only when it validates against its matching
turn.

**Files to create:**
- `src/middleware/conversation.py`

**Files to modify:**
- `src/middleware/config.py`
- `configs/middleware.yaml`
- `src/middleware/app.py`
- `tests/test_conversation.py`

Configuration keys:

- `conversation_max_turns: 8`
- `conversation_max_history_chars: 8000`
- `conversation_max_question_chars: 16000`

Environment overrides follow the existing config loader. Clamp values to
documented safe maxima and log one warning rather than accepting an unbounded
payload.

## Step 3: Make `ChatSession` the memory owner

Add `history: list[dict]` and a generated local `session_id` to
`scripts/chat.py::ChatSession`.

For each successful query:

1. Send the selected existing history plus the new raw question.
2. Append the user turn only after the server accepts the request.
3. Append the assistant turn only after a terminal answer/metadata event.
4. Do not append failed, cancelled, validation-error, or incomplete streamed
   requests.
5. Store only the response fields needed by follow-up resolution: answer text,
   detected/resolved tickers, intent, grounding, and timeframe when present.

Keep each `ChatSession` independent. No module-level history, mutable default,
or global “last ticker” may be introduced.

**Files to modify:**
- `scripts/chat.py`
- `tests/test_chat_client.py`

## Step 4: Add explicit session controls

Add these commands:

- `/new` and `/clear` — clear turns, create a new local `session_id`, and keep
  explicit CLI settings such as `/grounding` and `/autorefresh`;
- `/history` — show turn number, role, and a short local preview without making
  an API request;
- `/history off|on` — disable or enable sending/recording history for privacy
  or single-turn comparisons.

Never persist conversations to disk in Phase 2.2.2.1. A future opt-in export
may be designed separately with explicit redaction and retention semantics.

Update help and user documentation.

**Files to modify:**

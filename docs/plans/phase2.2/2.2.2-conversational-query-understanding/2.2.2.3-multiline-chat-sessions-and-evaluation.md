# 2.2.2.3 — Multiline Chat Sessions & Evaluation

## Objective

Make `scripts/chat.py` comfortable for natural research prompts: add a simple
multiline composer, visible session/history controls, friendly validation
errors, and an end-to-end offline integration test proving that verbose and
follow-up questions reach the middleware contract intact.

## Why This Matters

The current REPL sends every line immediately. Pasting a structured request can
create several unrelated questions, and the 2,000-character API limit appears
as a clipped HTTP error. Conversation support will still feel constrained if
the front door cannot compose or inspect a multi-part question safely.

## Step 1: Add a dependency-free multiline composer

Add `/ask` to enter multiline mode:

```text
you> /ask
... Compare NVDA and AMD revenue growth from FY2023 to FY2025.
... Include margin changes and summarize the strongest cited risk for each.
... /send
```

Commands while composing:

- `/send` — join lines with `\n`, validate locally, and submit once;
- `/cancel` — discard the buffer without changing history;
- `/preview` — show character count and the exact buffered text;
- EOF or `Ctrl+C` — cancel the buffer, not the entire session.

Do not add `prompt_toolkit`, Textual, or another TUI dependency. Reuse `input()`
and a small pure `MultilineBuffer` helper that is straightforward to test.

Single-line questions remain unchanged.

**Files to modify:**
- `scripts/chat.py`
- `tests/test_chat_client.py`

## Step 2: Surface limits and errors clearly

Read advertised limits from the `/health` capabilities block when available,
falling back to local defaults. Before sending:

- show `current/max` characters when the question is over 80% of its limit;
- reject an oversized local buffer without sending it;
- print the full structured FastAPI validation detail for 422 responses rather
  than clipping it to 200 characters;
- never mark streaming unsupported because of a 400/401/403/409/422 response;
- mark the stream endpoint unavailable only for the documented 404/405
  capability response.

Add effective history and multiline capability flags to `/health` so the
client can work against older middleware versions defensively.

**Files to modify:**
- `src/middleware/models.py`
- `src/middleware/app.py`
- `scripts/chat.py`
- `tests/test_chat_client.py`
- `tests/test_latency_optimizations.py`

## Step 3: Make session state visible but restrained

Update the prompt and metadata display:

- show a compact session suffix such as `session 7f2a · 4 turns`;
- when context was carried, print `context: AMD · revenue · FY2025` only in
  verbose mode;
- show when history was truncated or a topic reset was detected;
- `/history` displays local previews and never prints hidden system prompts,
  tool schemas, or full retrieved evidence;
- `/new` confirmation states that history was cleared.

Do not echo the standalone retrieval query by default. It is diagnostic
metadata available through `/verbose`, not a replacement for the user's text.

**Files to modify:**
- `scripts/chat.py`
- `scripts/CHAT.md`
- `tests/test_chat_client.py`

## Step 4: Add conversation-aware eval convenience

Extend `/eval`:

- `/eval 10` keeps the current single-turn behavior;
- `/eval conversations [N]` runs the conversation fixture subset;
- print carryover, topic-reset, subquestion-coverage, and leakage metrics when
  present;
- the command invokes the existing eval process and does not load/start the
  model itself.

Document that live evaluation is opt-in and requires an already available
stack; offline unit tests use injected runners only.

**Files to modify:**
- `scripts/chat.py`
- `scripts/CHAT.md`
- `eval/README.md`
- `tests/test_chat_client.py`

## Testing

Add offline tests:

- `test_multiline_buffer_preserves_newlines_and_punctuation`.
- `test_send_submits_exactly_one_question`.
- `test_cancel_and_interrupt_do_not_submit_or_change_history`.
- `test_oversized_multiline_question_is_not_sent`.
- `test_422_prints_structured_validation_detail`.
- `test_422_does_not_disable_streaming`.
- `test_old_server_without_conversation_capability_still_works`.
- `test_verbose_metadata_shows_carried_context`.
- `test_history_preview_does_not_expose_evidence_trace`.
- `test_conversation_eval_command_uses_expected_runner_arguments`.

No test starts the middleware, eval model, or browser.

## Verification Checklist

- [ ] `/ask`, `/send`, `/cancel`, and `/preview` support multiline prompts
- [ ] No new TUI dependency is introduced
- [ ] Current question is submitted once and preserved exactly
- [ ] Limits and 422 validation errors are visible and actionable
- [ ] Validation failures do not poison streaming capability detection
- [ ] Session, carried-context, truncation, and reset state are inspectable
- [ ] Older servers remain usable
- [ ] `/eval conversations` is documented and testable offline
- [ ] All client tests use mocked HTTP/SSE/process boundaries

# 2.2.3.2 — Deterministic Finance Tool Routing

## Objective

Route safe analytical, comparison, projection, and bounded calculation
requests to the existing finance tools with deterministic rules before model
generation. The model may explain routed results, but it must not be responsible
for deciding whether an exact database operation should happen.

## Why This Matters

The current tool loop depends on the local model emitting a valid
`tool_calls` payload. That adds latency and makes identical questions take
different paths. Finance operations such as "lowest forward P/E", "compare
NVDA and AMD revenue", and "NVDA next-year consensus" already have structured
inputs and safe handlers. A small rule router makes those paths faster,
repeatable, and easier to test while retaining the existing hybrid path for
qualitative or ambiguous asks.

## Step 1: Define route decisions and abstention

Create `src/middleware/deterministic_router.py` with:

- `ToolInvocation`
  - `name: str`
  - validated `arguments: dict`
  - `subquery_id: str`
  - stable `reason_code: str`.
- `CalculationSpec`
  - operation from `difference|percent_change|ratio|spread|rank`.
  - named operands that point to tool-result fields.
  - requested display unit and precision.
- `RouteDecision`
  - `matched: bool`
  - `complete: bool` — whether routed evidence can answer the full request.
  - ordered `tool_invocations` and optional `calculations`.
  - `requires_documents: bool`.
  - `reason_codes` and an `abstain_reason`.

`route(plan, available_metrics)` must be a pure function. It may inspect the
`QueryPlan` and known metric names but cannot access the network, call the
model, or mutate storage.

Abstain rather than guess when:

- an entity, metric, period, threshold, sort direction, or calculation operand
  is ambiguous;
- the requested metric is absent from `list_metrics`;
- qualitative evidence is required to answer a "why", risk, news, transcript,
  or filing question;
- the request would require a write tool.

**Files to create:** `src/middleware/deterministic_router.py`.

## Step 2: Map safe finance intents to existing tools

Use an explicit routing table:

| Request shape | Existing tool | Required arguments |
|---|---|---|
| one ticker + known metrics | `get_fundamentals` | `ticker`, `metrics` |
| rank/filter/threshold known metric | `query_facts` | `metric`, optional `tickers`, `order`, `limit`, `op`, `value` |
| compare tickers on one known metric | `query_facts` | ordered `tickers`, `metric`, `latest_only` |
| next-quarter/year estimates | `get_estimates` | `ticker`, optional `horizon` |
| price-target consensus | `get_price_targets` | `ticker` |
| management guidance | `get_guidance` | `ticker` |
| cached macro snapshot | `get_macro_snapshot` | none |
| cached sentiment summary | `get_sentiment` | `ticker`, bounded `days` |

Rules must be conservative:

- A compound numeric-plus-qualitative request executes the safe tools but sets
  `complete=False` and `requires_documents=True`; the orchestrator then uses
  standard or complex retrieval for the missing portion.
- Projection routing reports sourced consensus only. It never creates a target
  or forecast.
- `refresh_data` is never selected automatically. Existing refresh and
  fetch-on-miss policy remains the only side-effect path.
- No raw SQL, free-form expression evaluation, dynamic imports, or model-made
  tool names.

## Step 3: Reuse the guarded dispatcher

Extend `src/middleware/tools/base.py` with
`dispatch_named_tool(name, arguments, store, ctx)`:

- Resolve the tool from the existing registry.
- Reuse the existing JSON-schema argument validation and write guard.
- Return the same structured result shape and logging as `dispatch_tool()`.
- Make `dispatch_tool()` parse the model payload, then delegate to
  `dispatch_named_tool()`; there must be one validation/dispatch
  implementation.

The deterministic executor constructs a read-only `ToolContext` and caps
execution at three tool invocations per request. Handler errors are attached to
that invocation and cause the orchestrator to fall back to the normal
retrieval lane; they never fail `/query`.

**Files to modify:** `src/middleware/tools/base.py`.

## Step 4: Add a whitelisted calculator

Implement calculation helpers inside
`src/middleware/deterministic_router.py`:

- Use `decimal.Decimal` for values originating in finance facts.
- Support only difference, percent change, ratio, spread, and rank.
- Reject divide-by-zero, missing units, incompatible units, and missing
  periods with a structured error.
- Preserve operand values, units, periods, formula, and result in the output so
  2.2.4.3 can create provenance for derived numbers.
- Never call Python `eval()` or accept an arbitrary expression string.

A deterministic answer may skip model generation only when every obligation
in the plan is covered by tool/calculation results. Use short templates for
exact lookup, ranking, threshold, and comparison results. Projection templates
must include the existing estimates/not-guarantees caveat. Otherwise pass the
structured results to the normal answer generator.

## Step 5: Add feature controls

Add:

- `enable_deterministic_tool_routing: bool = False`
- `max_deterministic_tools_per_query: int = 3`
- `enable_deterministic_answers: bool = False`

to `src/middleware/config.py` and `configs/middleware.yaml`. Environment
overrides must follow the existing parsing pattern. The initial default is off
so 2.2.3.4 can compare the route against the current tool loop before enabling
it.

**Files to modify:** `src/middleware/config.py`,
`configs/middleware.yaml`.

## Testing

Create `tests/test_deterministic_router.py`:

- `test_lowest_pe_routes_to_query_facts`.
- `test_comparison_preserves_ticker_order`.
- `test_price_target_routes_to_consensus_tool`.
- `test_numeric_plus_risk_is_incomplete_and_requires_documents`.
- `test_unknown_metric_abstains_without_tool_call`.
- `test_router_never_selects_refresh_data`.
- `test_named_dispatch_reuses_schema_validation`.
- `test_tool_failure_falls_back_without_raising`.
- `test_calculations_use_decimal_and_keep_operands`.
- `test_divide_by_zero_returns_structured_error`.
- `test_complete_deterministic_answer_needs_no_model_call` using a mocked model
  client that must remain untouched.

Use seeded in-memory SQLite and mocked Chroma. Do not start middleware or the
model.

Quality gate: at least 95% routing accuracy and 100% write-tool avoidance on a
checked-in route matrix. Latency gate: routing plus argument construction has
p95 below 5 ms in the offline benchmark; complete deterministic cases make
zero planning or generation calls.

## Verification Checklist

- [ ] Route decisions are pure, explicit, and capable of abstaining
- [ ] Safe analytical/comparison/projection requests map to existing read tools
- [ ] Compound qualitative requests retain a standard/complex retrieval path
- [ ] Model tool invocation is not required for deterministic routes
- [ ] `refresh_data`, raw SQL, and arbitrary expressions are unreachable
- [ ] Named dispatch shares existing validation, guards, and logging
- [ ] Calculations are whitelisted, Decimal-based, and provenance-ready
- [ ] Feature flags reproduce the current path when disabled
- [ ] Offline routing accuracy is at least 95%; router p95 is below 5 ms
- [ ] `tests/test_deterministic_router.py` passes offline

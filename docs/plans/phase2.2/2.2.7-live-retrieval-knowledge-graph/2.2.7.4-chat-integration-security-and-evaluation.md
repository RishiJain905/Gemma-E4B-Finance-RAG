# 2.2.7.4 — Chat Integration, Security & Evaluation

## Objective

Connect `scripts/chat.py` to the live graph, secure the observer for local use,
measure trace completeness and overhead, and document the difference between a
retrieval observability graph and GraphRAG used as a retrieval architecture.

## Why This Matters

The graph should be one command away while chatting and safe to leave open on a
side monitor. It also introduces a new view into questions, evidence excerpts,
source URLs, and errors. Loopback defaults, redaction, bounded memory, and
explicit exposure rules are required before the feature can be enabled.

## Step 1: Add chat commands and query links

Add to `scripts/chat.py`:

- `/graph` — open the effective graph URL in the default browser and print it;
- `/graph url` — print without opening;
- `/graph trace` — open the latest completed/current query id;
- `--open-graph` — open once after middleware capabilities are available;
- terminal metadata `trace=<short query id>` when observer data exists.

Use Python's standard-library `webbrowser` module. If browser opening fails,
print the URL and continue. The command must not start another middleware or
model process.

`/health.capabilities` reports `graph_observer`, `graph_url`, and observer
limits only when enabled. Older servers remain compatible.

**Files to modify:**
- `scripts/chat.py`
- `src/middleware/app.py`
- `src/middleware/models.py`
- `tests/test_chat_client.py`

## Step 2: Enforce local-safe defaults

- observer/UI disabled by default;
- middleware stack scripts continue binding to `127.0.0.1` by default;
- same-origin UI/API/SSE;
- Content Security Policy allows only locally served scripts/styles and
  same-origin connections;
- `Cache-Control: no-store` on trace/corpus detail endpoints;
- no cookies, localStorage, service worker, analytics, or external font/script
  requests;
- sanitize labels/excerpts as text, never `innerHTML` from corpus/query data;
- validate source links as `http`/`https` before rendering;
- apply existing local API rate/size bounds plus observer-specific limits.

Reject graph API/static requests whose client address is not loopback. Remote
observer exposure is outside Phase 2.2 and requires a separate future design
covering authentication, TLS, proxy trust, and retention. Do not add a bypass
flag or reuse SEC/FRED/model credentials.

**Files to modify:**
- `src/middleware/graph_api.py`
- `src/middleware/config.py`
- `configs/middleware.yaml`
- `tests/test_graph_api.py`

## Step 3: Add completeness and noninterference tests

For seeded offline query contexts, assert:

- every executed subquery/stage/tool/evidence/source/citation appears once;
- no node claims an unexecuted stage or unused evidence;
- every `supports`/`cited_by` edge resolves to the final evidence ledger;
- blank/dropped evidence is visibly marked or omitted according to policy;
- legacy, fast, standard, complex, corrective, degraded, and error paths end in
  a valid terminal graph state;
- observer disabled yields no deltas and byte-compatible query responses aside
  from omitted optional metadata;
- observer exceptions/slow subscribers do not alter answer or latency budgets;
- two concurrent queries never share nodes/edges.

Add a golden JSON trace fixture for schema compatibility. Do not snapshot
pixel positions; layouts are UI behavior, while graph meaning is the contract.

## Step 4: Measure overhead and usability

Offline gates:

- graph event publishing p95 below 2 ms;
- observer adds no awaited browser work to the query path;
- normal trace snapshot contains 100% of expected executed graph elements;
- ring/element/excerpt/page limits hold under stress fixtures;
- zero canary secrets/local paths appear in API/static UI output;
- observer-disabled behavior has no required response changes.

Local browser gates during implementation:

- a new query becomes visible within 250 ms of the server publishing its first
  event on localhost;
- the user can select evidence and reach source/ticker/period/relevance detail
  in at most two interactions;
- filtering and corpus expansion never exceed visible element caps;
- disconnect/reconnect/reset and reduced-motion flows work without console
  errors.

These measurements do not require model generation: use a mocked/offline query
event producer. A later optional live smoke may run only when the GPU is
explicitly available.

## Testing

All required automated tests run with seeded stores, mocked query contexts,
and static assets. They do not start `chat.py`, a real browser, middleware
process, network source, or model. Browser/live checks are separate explicit
implementation verification activities.

## Verification Checklist

- [ ] `/graph` opens/prints the effective local URL without starting the model
- [ ] Query responses expose an optional trace id only when enabled
- [ ] Loopback, CSP, no-store, sanitization, and no-third-party defaults are enforced
- [ ] Non-loopback graph requests are rejected with no Phase 2.2 bypass
- [ ] Graph traces are complete, truthful, query-isolated, and noninterfering
- [ ] Disabled observer preserves the existing query contract
- [ ] Event, snapshot, redaction, and browser-usability gates are measurable
- [ ] Docs clearly distinguish observability graph from GraphRAG retrieval
- [ ] Results file is created only after implementation/evaluation

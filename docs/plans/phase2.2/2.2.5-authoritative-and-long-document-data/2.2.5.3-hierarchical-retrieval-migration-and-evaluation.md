# 2.2.5.3 — Hierarchical Retrieval Migration & Evaluation

## Objective

Backfill existing parsed SEC filings into the section/child index, retrieve
precise child hits with bounded parent/sibling expansion, merge authoritative
CompanyFacts where appropriate, and prove the new long-document path improves
evidence recall without increasing prompt size.

## Why This Matters

Flat chunk retrieval can return a sentence without its heading, table context,
or neighboring explanation. Sending an entire filing is worse: it increases
prefill latency and makes relevant evidence harder for the local model to use.
A natural hierarchy—filing -> section -> child chunk—supports precise search
and controlled reconstruction without the ingestion cost and hallucination risk
of generated RAPTOR summaries.

## Step 1: Add a bounded hierarchical expander

Create `src/middleware/hierarchical_retrieval.py` with
`expand_filing_hits(hits, store, obligations, context_budget)`.

For each top child hit:

1. Keep the exact hit and section heading.
2. Add at most one preceding and one following child from the same section when
   needed to complete a sentence/table.
3. Add an adjacent section only when a requested obligation matches its heading
   or the evidence grader reports missing local context.
4. Deduplicate shared parent/sibling chunks across hits.
5. Stop before the shared context budget is exceeded.

Never return an entire 10-K parent. Preserve every expanded item's original
retrieval score plus `expansion_reason` and `root_hit_id`.

## Step 2: Prefer authoritative structured facts without hiding conflicts

Integrate `Store.get_companyfacts()` from 2.2.5.1 into structured retrieval for
supported metrics and periods.

Selection policy:

- exact SEC CompanyFacts concept/unit/period/as-of match wins for filed GAAP
  facts;
- estimates remain separate and never overwrite realized facts;
- Yahoo/legacy fundamentals may fill unsupported or more current market fields;
- conflicting values remain separate evidence items with source/period/unit and
  a conflict reason;
- the evidence grader requires visible conflict disclosure instead of silently
  averaging or picking a convenient value.

Do not overwrite the legacy `fundamentals` table. Merge at retrieval/evidence
normalization so rollback remains possible.

## Step 3: Build an idempotent backfill command

Create `scripts/index_sec_filing_text.py`:

- default `--dry-run` reports eligible filings, parsed artifacts, estimated
  parent sections/chunks, missing files, and current indexed counts;
- `--apply` indexes one filing at a time through `FilingProcessor`/Store APIs;
- `--ticker`, `--accession`, and `--limit` support a pilot slice;
- `--resume-manifest <path>` records completed accession plus source-file hash;
- `--backup` snapshots only the affected Chroma collection directory before
  the first write;
- re-running unchanged input skips it; changed parsed artifacts replace their
  section families;
- interruption leaves the last filing retryable and prior filings valid.

Before any fan-out, run one filing pilot and compare section/chunk counts and
sample bodies. Do not call the parser model; migrate existing parsed artifacts.

## Step 4: Add long-document evaluation cases

Create a checked-in, copyright-safe fixture corpus with synthetic/excerpt-sized
filing sections and labeled evidence ids. Add cases requiring:

- one exact section child;
- heading plus child context;
- adjacent table/prose chunk;
- two distant sections in one filing;
- fact plus filing explanation;
- the same concept across annual and quarterly periods;
- missing/conflicting evidence.

Compare:

1. flat child retrieval;
2. flat retrieval with a larger top-k;
3. hierarchical child retrieval plus bounded expansion.

Report Recall@5/10, context precision, subquestion coverage, answer correctness,
prompt characters/tokens, expansion counts, retrieval latency, and unsupported
numeric claims.

## Step 5: Define promotion and rollback

Enable hierarchical expansion by default only when:

- long-document evidence Recall@10 improves at least 8 points;
- context precision does not regress more than 0.02;
- packed context characters/tokens are no higher than the flat baseline;
- answer correctness does not regress more than 0.02;
- retrieval p95 adds no more than 20%;
- migration is idempotent and its restore procedure is tested;
- no ingestion-time model calls are added.

Configuration:

- `enable_hierarchical_retrieval: false` initially;
- `hierarchy_max_siblings: 2`;
- `hierarchy_max_adjacent_sections: 1`;
- `hierarchy_max_expanded_items` bounded by the context packer.

Rollback disables expansion and restores the Chroma backup if the backfill must
be reversed. CompanyFacts remains an additive source and can be disabled
independently.

## Testing

All tests use local fixtures and mocked embeddings. Cover budget enforcement,
same-parent neighbors, distant-section selection, deduplication, conflict
preservation, dry-run/apply/resume, changed-source replacement, interrupted
backfill, backup/restore metadata, and feature-disabled flat retrieval.

## Verification Checklist

- [ ] Retrieval expands precise children only within explicit budgets
- [ ] Entire filings are never injected into a prompt
- [ ] Expanded evidence retains root-hit and section provenance
- [ ] SEC facts are preferred by explicit policy while conflicts stay visible
- [ ] Legacy facts remain intact and rollbackable
- [ ] Backfill is dry-run-first, pilotable, resumable, idempotent, and reversible
- [ ] Long-document quality improves within prompt/latency gates
- [ ] No RAPTOR summary, GraphRAG index, or ingestion-time model call is required

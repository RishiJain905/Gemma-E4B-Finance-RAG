# 1.7.4 — Cache Freshness & Staleness-Aware Querying

## Objective

Implement a comprehensive cache freshness system — track when each data source was last updated per ticker, expose staleness-aware query endpoints in the middleware, and add on-demand refresh triggers so the system fetches fresh data before answering when cached data is stale.

## Why This Matters

The system currently has TTL values in `watchlist.yaml` and a `cache_meta` table, but:

1. **No staleness-aware querying** — the middleware doesn't check if data is fresh before answering. A user asking about NVDA at 2 PM might get data from yesterday's market close.
2. **No on-demand refresh** — if data is stale, there's no mechanism to fetch fresh data before generating an answer.
3. **No unified freshness view** — there's no endpoint that shows "NVDA fundamentals: 2h old (fresh), NVDA news: 18h old (stale), FRED GDP: 6h old (fresh)."

### Modified: `POST /query` — Staleness-Aware

Update the `/query` endpoint to check freshness before answering:

```python
@app.post("/query")
async def query(request: QueryRequest):
    """
    Answer a financial question with staleness-aware data fetching.

    Flow:
      1. Parse intent (tickers, metrics, timeframes)
      2. Check freshness for detected tickers
      3. If stale sources exist:
         a. If request.refresh=True (default), fetch fresh data first
         b. If request.refresh=False, use cached data with staleness warning
      4. Retrieve facts + documents
      5. Build augmented prompt
      6. Send to model
      7. Return answer with freshness metadata
    """
```

Add a `refresh` field to the query request model:

```python
class QueryRequest(BaseModel):
    question: str
    refresh: bool = True  # Auto-refresh stale data before answering
    include_sources: bool = True  # Include source citations
```

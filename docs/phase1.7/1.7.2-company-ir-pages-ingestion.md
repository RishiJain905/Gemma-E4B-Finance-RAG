# 1.7.2 — Company IR Pages Ingestion

## Objective

Create the Company Investor Relations (IR) pages ingestion module — scrape press releases, investor presentations, and earnings materials from company IR pages for core tickers, and store them in the hybrid RAG store.

## Why This Matters

Company IR pages are the most authoritative source for:
- **Press releases** — product launches, partnerships, acquisitions (before news outlets report them)
- **Investor presentations** — strategic updates, roadmaps, capital allocation plans
- **Earnings materials** — supplemental slides, non-GAAP reconciliations, segment breakdowns
- **Corporate events** — analyst days, investor conferences, shareholder meetings

SEC filings are backward-looking (quarterly reports). IR pages are forward-looking — they contain the narrative management wants investors to hear. This is the last data source listed in the README architecture that has no implementation.

## Step 1: Create the IR Ingestor

Create `src/macros/ir_ingestor.py`:

```python
"""
src/macros/ir_ingestor.py
Company IR pages ingestion — fetches press releases, investor presentations,
and earnings materials from company investor relations pages.

Sources:
  - Company IR RSS feeds (preferred — structured, reliable)
  - Company IR page scraping (fallback — HTML parsing)

Usage:
    ingestor = IRIngestor()
    ingestor.fetch_for_ticker("NVDA")
    ingestor.fetch_all_core()
"""
```

### Key Methods

**`fetch_for_ticker(ticker: str) -> dict`**
1. Look up the ticker in `TICKER_IR_MAP`
2. Try RSS feed first (structured, reliable)
3. Fall back to HTML scraping of the IR page
4. Parse each item into a structured document:
   - title, url, published_date, content/summary, doc_type (press_release / presentation / earnings_material / event)
5. Store in ChromaDB with metadata: `{ticker, source: "ir", doc_type, date, url}`
6. Return `{ticker, status, items_found, items_stored, errors}`

**`fetch_all_core() -> dict`**
- Iterate through all core tickers
- Call `fetch_for_ticker()` for each
- Return combined results

**`_parse_rss(feed_url: str) -> list[dict]`**
- Fetch and parse RSS/Atom feed
- Extract title, link, published date, description/summary
- Return list of parsed items

**`_scrape_ir_page(ir_url: str) -> list[dict]`**
- Fallback when no RSS feed exists
- Fetch the IR page HTML
- Look for common IR page patterns:
  - News/press release sections
  - Event calendars
  - Document download links (PDF presentations)
- Extract what's available

**`_classify_document(title: str, content: str) -> str`**
- Classify document type based on title/content keywords:
  - `"press_release"` — product launches, partnerships, earnings releases
  - `"presentation"` — investor decks, slide decks, PDF presentations
  - `"earnings_material"` — earnings call slides, supplemental data
  - `"event"` — analyst days, conferences, shareholder meetings
  - `"other"` — uncategorized

### Rate Limiting

- Respect `robots.txt` and `Crawl-Delay` directives
- Add a configurable delay between ticker fetches (default: 3s)
- Use a reasonable User-Agent header

## Step 2: Create the Config

Create `configs/ir.yaml`:

```yaml
# configs/ir.yaml
# Company IR pages ingestion configuration

request_delay: 3.0          # Seconds between ticker fetches
max_retries: 3
timeout: 30                 # HTTP request timeout in seconds

# User-Agent for IR page requests
user_agent: "TraceAlchemy Research (contact@tracealchemy.example.com)"

# Document types to store
doc_types:
  - press_release
  - presentation
  - earnings_material
  - event

# Max items to fetch per ticker per run
max_items_per_ticker: 20
```

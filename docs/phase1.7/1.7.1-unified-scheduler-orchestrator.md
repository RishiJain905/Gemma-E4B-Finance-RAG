# 1.7.1 — Unified Scheduler Orchestrator

## Objective

Create a unified scheduler orchestrator that wraps all data sources (Yahoo Finance, SEC EDGAR, FRED, GDELT, Earnings Transcripts) into a single entry point — manage staggered execution, shared TTL tracking, and coordinated run cycles from one class.

## Why This Matters

Right now each source has its own scheduling logic:

| Source | Scheduler? | Entry Point |
|--------|-----------|-------------|
| Yahoo Finance | Partial — `ingest_all()` exists, no TTL wrapper | `YFinanceIngestor` |
| SEC EDGAR | Full — `FilingScheduler` with TTL + discovery | `FilingScheduler` |
| FRED | None — manual `fetch_all_indicators()` | `FREDIngestor` |
| GDELT | None — manual `fetch_financial_news()` | `GDELTIngestor` |
| Earnings Transcripts | None — manual `fetch_all_core()` | `EarningsTranscriptIngestor` |

There's no single command to run "everything that's due." A cron job would need 5 separate calls with no coordination — risking API rate limits, overlapping runs, and no unified status reporting.

### Core Design

```python
class UnifiedScheduler:
    """
    Orchestrates all data source ingestion with:
      - Staggered execution (sources run sequentially with delays)
      - Shared TTL tracking via cache_meta table
      - Per-source health checks before execution
      - Partial-failure handling (one source failing doesn't kill others)
      - Unified status reporting
    """

    SOURCES = {
        "yfinance": {
            "class": "YFinanceIngestor",
            "ttl_key": "fundamentals",
            "weight": 1,       # Execution order (lower = first)
        },
        "sec_filings": {
            "class": "FilingScheduler",
            "ttl_key": "sec_filings",
            "weight": 2,
        },
        "fred": {
            "class": "FREDIngestor",
            "ttl_key": "macro",
            "weight": 3,
        },
        "gdelt": {
            "class": "GDELTIngestor",
            "ttl_key": "gdelt_news",
            "weight": 4,
        },
        "earnings_transcripts": {
            "class": "EarningsTranscriptIngestor",
            "ttl_key": "transcripts",
            "weight": 5,
        },
    }
```

### Key Methods

**`run_all_stale(force: bool = False) -> dict`**
- Iterates through all sources in weight order
- For each source, checks cache_meta freshness
- Skips sources whose TTL hasn't expired (unless force=True)
- Runs each source with a configurable inter-source delay (default: 2s)
- Returns a combined report: `{source: {status, duration_s, tickers_checked, errors, ...}}`

**`run_daily() -> dict`**
- Morning market-open run (~9:30 AM ET)
- Runs: Yahoo Finance fundamentals, FRED macro, SEC filing discovery
- Skips: GDELT (runs more frequently), Earnings Transcripts (weekly)

**`run_hourly() -> dict`**
- Intraday news check
- Runs: GDELT news only (6h TTL, but hourly check ensures no gap)
- Skips: everything else

**`run_weekly() -> dict`**
- Weekend deep-dive batch
- Runs: Earnings Transcripts, full SEC filing processing, cache refresh
- Skips: Yahoo Finance (daily is enough), FRED (daily is enough)

**`status_report() -> dict`**
- Returns freshness status for every source across all tickers
- Highlights stale entries, last-run timestamps, and error counts

### TTL Integration

The scheduler reads TTL values from `configs/watchlist.yaml`:

```yaml
schedule:
  fundamentals: 24    # Yahoo Finance fundamentals
  news: 6             # Yahoo Finance news
  macro: 24           # FRED macro indicators
  sec_filings: 12     # SEC filing discovery
  gdelt_news: 6       # GDELT global news
  transcripts: 168    # Earnings transcripts (weekly)
```

Each source's TTL is tracked in the existing `cache_meta` table with a unique `source` identifier (e.g., `"unified:yfinance"`, `"unified:gdelt"`).

### Staggered Execution

Between each source run, insert a configurable delay (default: 2 seconds) to avoid hammering APIs. Log the delay and cumulative elapsed time.

```python
import time

for source_name, source_config in self._ordered_sources():
    if not self._is_stale(source_name) and not force:
        results[source_name] = {"status": "skipped", "reason": "cache_fresh"}
        continue

    start = time.monotonic()
    try:
        result = self._run_source(source_name)
        results[source_name] = {
            "status": "success",
            "duration_s": round(time.monotonic() - start, 2),
            "details": result,
        }
    except Exception as e:
        results[source_name] = {
            "status": "error",
            "duration_s": round(time.monotonic() - start, 2),
            "error": str(e),
        }

    # Stagger delay (skip after last source)
    if source_name != self._ordered_sources()[-1]:
        time.sleep(self.inter_source_delay)
```

Add a `main()` entry point so the scheduler can be called from cron:

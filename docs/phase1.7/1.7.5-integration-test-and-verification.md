# 1.7.5 — Integration Test & Verification

## Objective

Create a comprehensive integration test suite for Phase 1.7 — verify the unified scheduler orchestrator, Company IR pages ingestion, resilience layer, and cache freshness system all work together correctly, handle failure modes gracefully, and produce accurate status reports.

## Why This Matters

Phase 1.7 is the **operational backbone** of the entire system. Unlike earlier phases that added individual data sources, this phase adds:

1. **Orchestration** — the unified scheduler that coordinates all sources
2. **A new data source** — Company IR pages (the last missing source)
3. **Resilience** — retry, circuit breakers, dead-letter queue
4. **Freshness awareness** — staleness tracking and on-demand refresh

These are cross-cutting concerns that touch every other module. A bug in the scheduler means no data gets ingested. A bug in the resilience layer means a flaky API crashes everything. A bug in freshness tracking means stale answers.

### Test Scenarios

**Scenario 1: Full Daily Run**
1. Create a fresh store
2. Run `UnifiedScheduler.run_daily()`
3. Verify all daily sources ran (YF, FRED, SEC)
4. Verify hourly/weekly sources were skipped
5. Verify cache_meta entries were created
6. Verify `GET /freshness` shows correct status

**Scenario 2: Staleness-Aware Query**
1. Seed store with stale data (old timestamps)
2. Query `/query` with `refresh=True`
3. Verify stale sources were refreshed before answering
4. Verify response includes freshness metadata

**Scenario 3: Circuit Breaker Recovery**
1. Configure a source to fail N times
2. Verify circuit breaker opens after threshold
3. Wait for recovery timeout (or mock time)
4. Verify circuit breaker recovers and source runs again

**Scenario 4: Dead-Letter Queue**
1. Configure a source to fail persistently
2. Run scheduler
3. Verify failed items appear in dead-letter queue
4. Fix the source, retry from DLQ
5. Verify items are removed from DLQ on success

**Scenario 5: IR Pages Integration**
1. Mock IR RSS feeds for all core tickers
2. Run `IRIngestor.fetch_all_core()`
3. Verify documents are stored in ChromaDB
4. Verify document types are classified correctly
5. Verify `GET /freshness` shows IR data as fresh

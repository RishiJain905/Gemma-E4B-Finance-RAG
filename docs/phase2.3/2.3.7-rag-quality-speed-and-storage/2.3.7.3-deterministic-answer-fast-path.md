# 2.3.7.3 — Deterministic Answer Fast Path

## Objective

Allow completely covered, read-only requests to return a validated deterministic
answer without paying local-model generation latency. Preserve grounded model
generation for qualitative, ambiguous, or partially covered questions.

Phase 2.2 already constructs `deterministic_answer` inside the adaptive
orchestrator, but the request path deliberately does not use it to bypass final
generation. This task completes that seam under stricter completeness and answer
contracts.

## Eligible requests

Initial allowlist:

- capability/coverage inventory from 2.3.7.1;
- exact stored fact lookup with unambiguous entity, metric, period, and unit;
- bounded ranking/filtering/comparison returned by structured tools;
- whitelisted Decimal calculations with resolved operands;
- freshness/source-status lookup;
- supported estimate, target, guidance, and macro snapshots with their existing
  caveats.

Ineligible requests include explanations, risks, news synthesis, sentiment
narratives, filing interpretation, conflicting evidence requiring judgment,
missing obligations, and any route that requested or performed a write.

## Step 1: Define a final-answer contract

The fast path requires:

```text
route matched
route complete under 2.3.7.2 obligations
all tool invocations succeeded
result completeness is known
evidence/provenance rows are present where required
no qualitative-document obligation remains
no unsupported conflict or stale-data policy violation remains
answer template validated
```

Return the normal `QueryResponse` shape with grounding, citations/evidence ids,
freshness, timings, orchestration, and optional evidence trace populated. Add:

```text
answer_origin: deterministic | model | degraded
generation_skipped: true|false
generation_skip_reason
```

## Step 2: Render compact typed templates

Keep templates small and explicit rather than building a generic prose engine.
Each template owns:

- value, unit, period/as-of rendering;
- exact count/list completeness language;
- source/citation display;
- conflict and staleness disclosure;
- estimates/not-guarantees caveats;
- empty-result behavior.

Do not pass deterministic output back through the model for rewriting.

## Step 3: Integrate before final generation

After adaptive orchestration and evidence normalization, check the final-answer
contract. If eligible:

1. build/validate the deterministic answer;
2. run deterministic citation/numeric validation;
3. finalize response metadata and graph/stream events;
4. return without calling the model endpoint.

Streaming requests emit normal progress metadata followed by the deterministic
answer as one bounded token/content event and one terminal metadata event. Tool
progress ordering remains compatible.

## Step 4: Preserve safe rollback

`enable_deterministic_answers` remains the single rollout flag. Off keeps the
pre-2.3.7 generation path. When on, only allowlisted complete routes skip the
model. Any renderer, validator, or response-finalization error falls soft to the
normal model path exactly once.

After one stable release and completed promotion results, remove obsolete
metadata-only branches that constructed an answer which could never be returned.

## Acceptance gates

- zero model calls for eligible complete requests;
- zero skipped model calls for ineligible/partial requests;
- deterministic values, units, periods, counts, citations, and caveats match the
  exact tool result;
- at least 90% end-to-end latency reduction versus model-generated equivalents
  on the local reference stack;
- response schema, graph trace, and streaming terminal behavior remain valid;
- feature-off output remains compatible with the Phase 2.2 path.

## Testing

- Mock the model endpoint and assert it is never called for every eligible class.
- Assert qualitative, partial, failed-tool, conflict, and stale-policy cases use
  the model path or an existing honest refusal.
- Compare deterministic counts/lists to complete Store results.
- Verify evidence ids and numeric validation resolve against the supplied ledger.
- Fault answer rendering and prove one model fallback, not an error or duplicate
  generation.
- Exercise both `/query` and `/query/stream` event ordering.
- Run feature-off compatibility fixtures.

## Verification Checklist

- [ ] Only fully covered allowlisted requests bypass generation
- [ ] Deterministic answers preserve provenance, freshness, and policy metadata
- [ ] Partial or qualitative requests cannot reach the fast path
- [ ] Renderer failure falls back to model generation once
- [ ] Streaming and graph traces truthfully show generation was skipped
- [ ] Measured end-to-end latency reduction meets the promotion gate

# 2.3.1.1 — Security Universe and Membership History

## Objective

Replace the hand-maintained ticker-only universe with canonical securities and
historical S&P 500/Nasdaq-100 membership. Every downstream source must resolve
work through this registry rather than copying a ticker list.

## Why This Matters

Tickers change, share classes coexist, constituents enter and leave indexes, and
one SEC CIK may cover multiple listed securities. A ticker string is therefore
not a durable identity. Without a registry, new ingestion will duplicate
companies, lose membership history, and make graph filters unreliable.

## Step 1: Add the additive schema

Add `securities`:

- `security_id` — stable internal opaque id;
- `ticker`, `normalized_ticker`, `company_name`, `exchange`;
- `cik` when applicable;
- `security_type`, `share_class`, `sector`, `industry`;
- `active`, `first_seen_at`, `last_seen_at`, `updated_at`;
- uniqueness on the normalized listed security, not CIK alone.

Add `security_aliases`:

- `security_id`, `alias`, `alias_type` (`ticker|vendor_symbol|former_ticker`);
- `valid_from`, `valid_to`, and `source`;
- one normalized alias may map to only one active security unless an explicit
  provider namespace is supplied.

Add `security_memberships`:

- `security_id`, `index_code` (`sp500|nasdaq100`);
- `effective_from`, nullable `effective_to`, `active`;
- `source`, `source_url`, `observed_at`;
- unique active membership per security/index.

Use idempotent DDL and indexes for active ticker, CIK, alias, active index
membership, sector, and last-seen queries.

## Step 2: Implement bounded universe providers

Create adapters for:

- Nasdaq's published Nasdaq-100 company list;
- IVV's downloadable holdings as the personal-use S&P 500 proxy;
- SEC's ticker/exchange/CIK mapping for identity reconciliation.

Adapters return records only. They do not write storage or decide coverage.
Downloaded rows are validated for expected headers, a plausible constituent
count, duplicate symbols, cash/derivative rows, and empty identifiers. If a
provider format changes, retain the previous active universe and mark the update
failed; never replace it with an empty or partial set.

## Step 3: Reconcile and preserve history

`UniverseRegistry.refresh()` performs one transaction:

1. normalize provider-specific symbols such as dot/dash share-class variants;
2. match by provider symbol, active alias, exchange, and CIK where available;
3. create a security only when no safe match exists;
4. open memberships for new constituents;
5. close memberships absent from a validated new snapshot;
6. record unresolved/ambiguous rows as reconciliation errors;
7. bump the Store revision once after a committed change set.

Do not delete a security because it leaves an index. Historical filings and
documents must continue to resolve.

## Step 4: Expose a small Store API

Required methods:

- `list_securities(index=None, active=True, sector=None, limit, offset)`;
- `get_security(ticker_or_id)`;
- `resolve_security(symbol, provider=None, as_of=None)`;
- `list_memberships(security_id=None, index_code=None, active=None)`;
- `upsert_universe_snapshot(source, observed_at, rows)`;
- `list_universe_errors(run_id)`.

Existing `list_tickers()` remains compatible and returns active canonical
tickers. It must not silently change to include historical aliases.

## Testing

- Parse pinned Nasdaq, IVV, and SEC fixtures without network access.
- Reconcile dot/dash symbols, two share classes under one CIK, former symbols,
  missing CIKs, and duplicate provider rows.
- Reject a malformed or implausibly small snapshot without changing active
  membership.
- Apply two snapshots and prove additions/removals create membership history.
- Replay the same snapshot and prove the database and revision are unchanged.
- Keep existing ticker resolution and Store tests passing.

## Verification Checklist

- [ ] Every valid constituent becomes one canonical security or one explicit error
- [ ] S&P 500/Nasdaq-100 overlap does not duplicate a security
- [ ] Multiple share classes under one CIK remain distinct securities
- [ ] Membership removals are closed, not deleted
- [ ] A bad provider snapshot cannot erase the current universe
- [ ] Provider adapters contain no persistence logic
- [ ] Store mutation bumps the revision once per changed snapshot

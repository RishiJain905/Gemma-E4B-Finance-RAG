# 2.3.1.2 — Coverage Tiers and Source Policy

## Objective

Define which sources run for which securities so broad coverage does not trigger
every expensive per-ticker ingestion path.

## Coverage Model

Use explicit scopes:

- **universe** — identity and membership maintenance;
- **broad** — all active S&P 500 or Nasdaq-100 securities;
- **deep** — the user's focused research list;
- **sector** — active securities matching configured sector rules;
- **global** — non-security-specific macro/regulatory sources.

A security may belong to several scopes. `deep` is an additive policy, not a
separate identity list.

## Default source policy

| Source capability | Default scope |
|---|---|
| Universe providers | universe |
| SEC event discovery and selected event documents | broad |
| Company news | broad |
| Daily market summary and corporate actions | broad |
| Full 10-K/10-Q filing text | deep |
| SEC CompanyFacts | deep initially; broad only after measured batch cost |
| IR pages, transcripts, estimates | deep |
| GDELT | deep and optional |
| Official macro feeds | global |
| openFDA, NHTSA, USAspending | matching sector rules |

This policy prevents the current `fetch_all_core()` methods from being reused as
an accidental full-universe fan-out.

## Step 1: Replace list semantics with a resolver

Add `CoverageResolver` with:

- `tickers_for(source_name, as_of=None)`;
- `scopes_for(security_id)`;
- `is_enabled(source_name, security_id=None)`;
- `explain(source_name, security_id=None)` for status/graph display.

The resolver reads canonical securities plus `configs/coverage.yaml`. It never
contacts a provider and never mutates membership.

## Step 2: Keep watchlist compatibility

Migrate the current `core` list into `deep.tickers`. Preserve a compatibility
reader for one release so existing ingestors continue to work while they are
converted. The `extended` list becomes optional explicit additions to `broad`,
not a second hidden policy.

Unknown deep tickers are validation errors unless explicitly configured as
`allow_outside_indexes`. This keeps intentional off-index research possible
without letting typos create work.

## Step 3: Make policy visible

Status and graph projections must expose:

- coverage scope;
- why the security is included (index membership, explicit deep list, sector);
- which source capabilities are enabled;
- the policy revision used for the run.

Do not expose secrets, raw YAML paths, or provider keys.

## Testing

- Resolve broad as the unique active index union.
- Resolve deep from current core tickers plus permitted off-index additions.
- Prove deep-only sources never receive the full broad universe.
- Prove overlapping scopes never schedule a ticker twice for one source/run.
- Validate unknown sources, invalid scopes, and unknown explicit tickers.
- Confirm legacy watchlist configuration produces a warning and the same deep
  list during the compatibility period.

## Verification Checklist

- [ ] Source work is selected by capability policy, not a shared core list
- [ ] Broad coverage includes the current index union without duplicates
- [ ] Deep sources remain bounded to explicitly selected securities
- [ ] Sector feeds run only for mapped sectors
- [ ] Off-index deep tickers require an explicit opt-in
- [ ] Policy decisions are deterministic and explainable

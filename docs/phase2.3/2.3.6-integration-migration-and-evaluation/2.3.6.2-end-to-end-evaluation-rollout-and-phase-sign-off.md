# 2.3.6.2 — End-to-End Evaluation, Rollout, and Phase Sign-Off

## Objective

Prove the expanded corpus is complete enough, refreshable, retrievable, and
usable in both graph modes before enabling broad-universe ingestion by default.
Final sign-off depends on the Phase 2.3.7 RAG quality, speed, feature-disposition,
and storage gates; this file remains the phase-wide integration gate.

## Step 1: Pilot one representative slice

Before full fan-out, enable a small set covering different evidence:

- ORCL — financing/capital-markets event path;
- NVDA — high-volume company news and existing GDELT behavior;
- AAPL — large, multi-source issuer with corporate actions;
- one healthcare security — openFDA mapping;
- one automotive security — NHTSA mapping;
- one government contractor — USAspending mapping;
- a small official macro catalog.

Run bootstrap, two identical refreshes, one simulated 429, one missing key, and
one indexing failure. Review normalized rows, retrieval, Live Trace, and Corpus
Explorer before expanding.

## Step 2: Expand in controlled stages

1. Pilot securities and official global feeds.
2. Nasdaq-100 broad scope.
3. Remaining S&P 500 union.
4. Sector feeds.
5. Optional deep-list expansion only after measured cost/storage review.

Each stage records elapsed time, requests/provider, quota use, new/duplicate/error
counts, SQLite/Chroma growth, retrieval changes, and graph performance. A failed
stage is disabled independently.

## Step 3: Add evaluation questions

Extend the golden set with:

- latest debt/equity raise and supporting primary filings;
- recent corporate action and market-date questions;
- company news across several broad-universe tickers;
- index/sector comparisons;
- Fed/Treasury/BLS/BEA/EIA release questions;
- historical-as-of questions using vintages and former memberships;
- unavailable/stale/source-conflict cases;
- citations spanning primary and corroborating sources.
- direct and indirect corpus-capability questions, including the exact complete
  active ticker set and count;
- deterministic fact/inventory questions that must bypass model generation;
- lexical exact-match and semantic hybrid queries at seeded scale;
- qualitative and partial-evidence questions that must retain grounded model
  generation.

The evaluator captures the exact evidence ledger delivered to generation.

## Step 4: Enforce phase acceptance gates

### Universe and ingestion

- 100% of validated source constituents resolve to canonical security or an
  explicit reconciliation error;
- two identical runs create zero duplicate canonical records/families;
- every enabled source reaches a truthful independent terminal status;
- simulated provider-wide 429 stops that provider after bounded attempts and all
  later sources still run;
- daily broad refresh fits configured free-tier budgets.

### Retrieval and evidence

- primary SEC/issuer/government evidence outranks duplicate secondary reporting
  for primary-source questions;
- financing/event queries retrieve the correct event and evidence in Recall@10
  on the labeled set;
- existing Phase 2.2 single-turn/conversational retrieval nDCG@10 regresses by no
  more than 2 points;
- all emitted citation ids resolve to supplied evidence;
- structured values are never sourced from an embedded numeric-row surrogate.

### RAG quality and speed

- explicit all-ticker inventory has set precision/recall 1.0, exact count, and
  zero invented tickers against the active canonical registry;
- indirect-query exact-plan accuracy improves by at least 15 percentage points
  over the measured baseline without materially regressing direct questions;
- eligible deterministic answers make zero model calls and reduce end-to-end
  latency by at least 90%;
- incomplete, conflicting, or qualitative requests never skip generation solely
  for speed;
- persistent lexical and hybrid retrieval meet the 2.3.7.5 latency, quality,
  revision, and fail-soft gates at 100,000 seeded items;
- the 2.3.7.6 storage benchmark records a keep/replace decision, and any database
  replacement remains a separately approved migration;
- every dormant feature has the final disposition required by 2.3.7.4.

### Graph and operations

- mixed-source Live Trace is complete, truthful, redacted, and non-interfering;
- Corpus Explorer handles 600 securities/100,000 metadata items under the 2.3.5.3
  bounds;
- all filters/counts/pagination remain revision-consistent;
- observer-disabled behavior remains compatible;
- setup/status/graph outputs contain no canary secrets or local paths.

## Step 5: Run verification

During each numbered feature, run its scoped tests. Final offline exit gate:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\verify.ps1
```

Expected final line:

```text
VERIFY: PASS
```

Live provider tests are opt-in, serial, quota-aware, and never part of the
default offline suite. Browser smoke uses a seeded/mocked corpus; a live model is
not required to validate Corpus Explorer.

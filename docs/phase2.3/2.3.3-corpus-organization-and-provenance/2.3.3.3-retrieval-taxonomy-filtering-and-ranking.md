# 2.3.3.3 — Retrieval Taxonomy, Filtering, and Ranking

## Objective

Make the expanded corpus retrievable by stable finance concepts rather than
provider names, while preferring primary and timely evidence.

## Stable taxonomy

### Source categories

`sec|issuer|market_data|company_news|central_bank|treasury|economic_agency|
regulator|sector_agency|transcript|estimates|global_news`

### Item types

`filing|filing_exhibit|press_release|news|speech|policy_release|
economic_release|market_observation|corporate_action|regulatory_event|
contract_award|recall|transcript|estimate`

### Event types

Use the SEC/company event vocabulary from 2.3.2.1 plus stable macro/sector events.
Provider-specific labels are retained as metadata but never become UI/retrieval
facets without normalization.

## Step 1: Extend filters and intent routing

Normalized evidence and Store search support:

- security/ticker/alias;
- index membership and sector/industry;
- source category and specific source;
- item and event type;
- form/item/exhibit;
- published/effective/as-of date range;
- freshness/indexing status and authority tier.

Intent parsing recognizes financing, corporate action, ownership, regulatory,
macro release, and company-news requests. It should not require the user to name
the provider.

## Step 2: Apply authority-aware ranking

Base authority order:

1. direct SEC/issuer/government/regulator evidence;
2. structured direct market/economic observations;
3. licensed API news/provider summaries;
4. transcripts/estimates with their existing semantics;
5. global discovery sources such as GDELT.

Authority does not erase relevance. Use it as a deterministic tie/boost after
semantic/lexical relevance and exact entity/date/type matches. Recency weight is
strong for "latest" and event/news queries, weak for historical filings.

When multiple sources describe one event, pack the primary record plus at most a
bounded number of materially different secondary records. Do not fill context
with syndicated duplicates.

## Step 3: Preserve temporal meaning

Distinguish:

- publication/filing time;
- event/effective time;
- observation period;
- source vintage/as-of time;
- ingestion/access time.

`latest` uses the appropriate domain timestamp, not `ingested_at`. Historical
questions use membership/alias state as of the requested period when available.

## Step 4: Make evidence self-describing

Prompt and Live Trace evidence metadata includes item/event type, authority tier,
source, date semantics, canonical security, and coverage tier. Citations continue
to resolve to exact evidence ledger ids.

## Testing

- Filter a mixed seeded corpus by every stable facet.
- Rank a direct SEC financing filing above secondary vendor news for the same
  event while retaining the secondary result when useful.
- Apply recency to latest-news queries without penalizing historical filings.
- Resolve former/current ticker aliases by the requested period.
- Suppress duplicate syndicated stories from the packed context.
- Prove citations and graph nodes carry the same taxonomy metadata.

- [ ] Index, sector, event, source, and date filters work together
- [ ] Duplicate coverage does not consume the evidence budget

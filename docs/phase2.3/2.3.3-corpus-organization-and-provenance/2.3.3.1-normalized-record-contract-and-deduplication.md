# 2.3.3.1 — Normalized Record Contract and Deduplication

## Objective

Define the smallest common boundary between provider adapters and storage so
every source preserves provenance, deduplicates predictably, and appears under a
stable corpus taxonomy.

## Record families

Do not force every payload into one universal object. Use three focused records:

### `NarrativeRecord`

For news, filings/exhibits, releases, speeches, minutes, recalls, awards, and
other text:

- provider/source identity and provider record id;
- stable `corpus_item_id`;
- item type and optional event type;
- title, bounded summary/body, language;
- published/effective/as-of/accessed timestamps;
- source URL and optional canonical URL;
- canonical security ids/tickers, index/sector facets;
- content hash and metadata allowlist;
- document family/indexing status.

### `ObservationRecord`

For prices, volumes, rates, economic series, and other numeric values:

- metric/series id, value text/numeric, unit, frequency;
- observation period and vintage/as-of time;
- security or global/sector scope;
- provider identity and source URL.

### `EventRecord`

For classified company/regulatory events and corporate actions:

- stable event type, effective/announced dates, status;
- linked security ids and source corpus item ids;
- typed optional fields such as amount, currency, rate, ratio, or action dates;
- classifier/rule version and explanation where derived;
- provider identity and provenance.

Use frozen dataclasses or equally explicit typed models. Avoid a framework-sized
validation dependency.

## Step 1: Add a corpus metadata ledger

Add `corpus_items` in SQLite as the searchable bridge to narrative content. It
stores metadata and indexing state, not a second full document body.

Required uniqueness:

- primary: `(source, provider_record_id)` when the provider has a durable id;
- fallback: `(source, canonical_url, published_at)`;
- final controlled fallback: `(source, content_hash)`.

Add `corpus_item_sources` so one deduplicated item can retain several provider or
publisher origins. Add `corpus_item_securities` for many-to-many security links.

## Step 2: Use deterministic deduplication layers

Apply in order:

1. provider identity;
2. normalized canonical URL;
3. exact content hash;
4. conservative normalized headline plus publication-window key for syndicated
   news only.

Do not automatically merge by embedding similarity or broad fuzzy title match.
False merges are more harmful than visible near-duplicates in financial evidence.

When a duplicate arrives, update access/provenance metadata and link the new
source; re-embed only if the canonical narrative content changed.

## Step 3: Preserve source authority

Every record carries:

- `source_name` and stable `source_category`;
- provider id and original source/publisher where different;
- source/canonical URLs;
- published, observed, accessed, and ingested timestamps;
- license/content policy label;
- normalization version.

No adapter may label vendor-parsed filing text as direct SEC evidence.

## Step 4: Make writes atomic

Store operations commit the metadata record, security links, event/observation
rows, and indexing status coherently. Chroma indexing may follow, using
`pending|indexed|error|not_applicable`. Failed embeddings remain discoverable in
status and can be retried without refetching the provider payload.

## Testing

- Validate all required fields and reject unbounded/unknown metadata keys.
- Replay provider ids, URLs, and hashes and prove zero duplicate items.
- Merge syndicated news provenance without merging two distinct same-day stories.
- Link one event/item to multiple securities without duplicating the item.
- Simulate Chroma failure and prove the SQLite item remains retryable.
- Change narrative content and prove only the affected family is re-indexed.

## Verification Checklist

- [ ] Provider adapters emit one of three explicit record families
- [ ] Every item has stable identity, provenance, and timestamps
- [ ] Deduplication is deterministic and conservative
- [ ] Multi-source provenance survives deduplication
- [ ] Metadata commits do not depend on embedding availability
- [ ] Complete narrative bodies are not duplicated into SQLite

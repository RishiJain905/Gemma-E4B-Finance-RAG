# 2.3.2.1 — SEC Event and Capital-Markets Ingestion

## Objective

Turn SEC EDGAR into the authoritative broad-universe event feed, including the
forms and exhibits needed to detect debt raises, equity offerings, shelf
registrations, acquisitions, earnings, guidance, governance, and ownership
changes.

## Why This Matters

The current discovery path focuses on `10-K`, `10-Q`, and `8-K` for a small core
list. A company raising money may first appear in an `S-3ASR`, `424B5`, free
writing prospectus, material agreement, or 8-K exhibit. Those documents must be
discoverable without polling every company's complete submission history.

## Step 1: Add index-driven discovery

Use SEC daily index files for incremental discovery:

1. load the active broad-universe CIK set;
2. download each unprocessed daily index once;
3. filter rows locally by CIK and configured forms;
4. register unseen accessions;
5. advance the daily-index cursor only after registration commits.

Bootstrap uses SEC submissions/bulk data. Incremental refresh does not loop over
550 submissions endpoints. Respect the existing declared user agent and SEC fair
access limits.

Forms include:

- periodic/material: `10-K`, `10-Q`, `8-K`, amendments, `6-K`;
- capital markets: `S-1`, `S-3`, `S-3ASR`, amendments, `424B2`, `424B3`,
  `424B5`, `FWP`;
- ownership/governance: `SC 13D`, `SC 13G`, amendments, `3`, `4`, `5`,
  `DEF 14A`.

Form selection belongs in config and is grouped by event capability.

## Step 2: Fetch only relevant documents and exhibits

For each new filing, retain filing metadata and fetch:

- the primary document;
- `EX-99.1` press releases;
- `EX-10` material agreements when referenced by an event rule;
- other exhibits explicitly allowlisted by form/item policy.

Do not fetch every exhibit blindly. Reuse existing filing parsing, sectioning,
and Chroma family indexing. Broad mode indexes selected event filings; deep mode
continues to index full periodic filings.

## Step 3: Classify deterministic event signals

Add a rule-based classifier that emits zero or more event labels:

- `debt_raise`, `equity_raise`, `convertible_offering`;
- `shelf_registration`, `prospectus_update`;
- `acquisition`, `divestiture`;
- `earnings_release`, `guidance_change`;
- `leadership_change`, `auditor_change`;
- `buyback`, `dividend_change`;
- `insider_transaction`, `beneficial_ownership_change`.

Rules may use form, 8-K item number, exhibit type, structured filing metadata,
and bounded heading/text patterns. They must include `rule_version` and
`classification_reason`; no model call is required during ingestion.

For a financing, preserve amount/currency/security type/maturity/rate only when
deterministically extracted. Unknown values remain null rather than guessed.

## Step 4: Maintain idempotence and provenance

The SEC accession is the provider identity. An event's stable key combines
accession, event type, and rule version. Reprocessing may update a classification
but cannot duplicate the filing, event, or document family.

Primary SEC URLs outrank vendor-parsed copies during retrieval.

## Testing

- Filter a daily-index fixture against a mixed CIK universe.
- Discover each configured form and ignore non-universe/unconfigured rows.
- Classify representative debt, equity, shelf, acquisition, earnings, ownership,
  and no-match fixtures.
- Prove an ORCL-like notes offering links its registration/prospectus/8-K evidence
  without inventing an amount.
- Replay index and filing payloads with no duplicate writes.
- Simulate a partial document failure and preserve the registered accession for a
  later retry.

## Verification Checklist

- [ ] Incremental discovery downloads an index once instead of polling per ticker
- [ ] Capital-markets forms and relevant exhibits are covered
- [ ] Event labels are deterministic, versioned, and explainable
- [ ] Primary SEC provenance is retained through retrieval and graph display
- [ ] Broad event indexing and deep full-filing indexing remain distinct
- [ ] A filing/document failure does not stop other accessions or sources

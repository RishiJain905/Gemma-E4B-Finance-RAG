# 2.3.2.2 — Company News, Market Data, and Corporate Actions

## Objective

Add broad-universe company news and efficient daily market/corporate-action data
through Finnhub and Massive, with explicit entitlements, quotas, and source
fallbacks.

## Provider responsibilities

### Finnhub

- company news since the stored ticker cursor;
- provider-supplied headline, summary, source, URL, timestamp, and identifiers;
- optional profile/calendar metadata only when entitled and useful.

### Massive

- grouped US daily market summary, filtered locally to the active universe;
- splits, dividends, and other entitled corporate actions;
- optional news as secondary coverage/deduplication input;
- optional vendor-parsed filing metadata as secondary evidence, never a
  replacement for SEC.

The adapter must treat a plan/entitlement response as `disabled_entitlement`, not
retry it as a transient failure.

## Step 1: Implement small provider adapters

Each adapter owns HTTP request/response translation, authentication, pagination,
provider error parsing, and raw-to-normalized conversion. It does not own Store
schema, Chroma chunking, coverage selection, or scheduler policy.

Use standard-library/installed HTTP clients; do not add a provider SDK unless it
materially reduces code and is already a project dependency.

## Step 2: Ingest news responsibly

Store only content returned by the API under the account entitlement:

- headline and provider summary;
- publisher/source name;
- canonical URL and publication timestamp;
- matched canonical securities;
- provider id and content hash.

Do not crawl the destination publisher. Deduplicate exact provider records first,
then canonical URL, then a conservative normalized headline/time-window key.
Do not use embedding similarity as the ingestion dedupe authority.

## Step 3: Store market data structurally

Persist daily OHLCV observations in SQLite and do not embed them. One Massive
grouped response is filtered locally to the broad universe. Rows include adjusted
state, market date, provider, accessed time, and provider revision metadata.

Corporate actions are structured events with effective/ex/payable/record dates
as applicable. Their narrative descriptions may be indexed, but numeric action
rows remain structured.

## Step 4: Define fallback behavior

- SEC remains authoritative for filings.
- Massive is the preferred broad daily grouped-market source when entitled.
- Existing Yahoo data remains a soft fallback/cross-check, not a reason to fail
  a successful Massive run.
- Twelve Data is optional and disabled unless explicitly configured.
- Finnhub and Massive news are both accepted; dedupe preserves all provenance
  links on the surviving corpus item.

## Testing

- Paginate Finnhub news with an overlap window and advance the cursor only after
  successful storage.
- Deduplicate identical/syndicated news while retaining both provider origins.
- Parse a grouped-market fixture and store only active-universe symbols.
- Upsert corrected daily bars without duplicate dates.
- Parse splits/dividends and replay them idempotently.
- Exercise 401/403, entitlement denial, 429 with retry metadata, malformed rows,
  and partial pages without network access.

## Verification Checklist

- [ ] A daily broad-market run does not make one price request per ticker
- [ ] News storage never crawls publisher pages
- [ ] Provider ids, timestamps, URLs, and access times survive normalization
- [ ] Market bars are structured and never embedded
- [ ] Duplicate news combines provenance without duplicating narrative chunks
- [ ] Missing/limited provider entitlements disable only that capability

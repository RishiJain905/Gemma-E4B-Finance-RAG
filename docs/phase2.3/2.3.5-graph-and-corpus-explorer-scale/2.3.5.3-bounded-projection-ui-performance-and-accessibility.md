# 2.3.5.3 — Bounded Projection, UI Performance, and Accessibility

## Objective

Extend the read-only corpus projection and graph APIs so the new information
architecture remains responsive and safe at Phase 2.3 scale.

## Phase 2.2 interaction baseline to preserve

The current Live Trace implementation projects the six DOM stage lanes through
Cytoscape's zoom/pan transform so the rail stays aligned after auto-fit, manual
pan/zoom, and resize. Dense stage buckets use bounded subcolumns rather than
forcing the entire trace to zoom out.

The sequence scrubber coalesces `input` events through
`requestAnimationFrame`. While scrubbing, nodes position instantly, entrance
animation is disabled, queued animations are cleared, and the viewport does not
auto-fit. Normal live animation/follow behavior resumes on scrub completion.

Phase 2.3 UI work must extend these behaviors rather than replace them with a
static grid rail, per-input render storm, or automatic fit during scrubbing.

## Step 1: Add aggregate Store queries

Add indexed, bounded queries for counts grouped by:

- index and coverage tier;
- sector/industry/security;
- source category/source;
- item/event type;
- year/month;
- freshness/indexing state.

Aggregates come from SQLite metadata tables. Do not enumerate all Chroma
documents to calculate each request. Existing Phase 2.2 source/ticker/fact/filing
methods remain compatible.

## Step 2: Extend corpus node vocabulary

Add source-independent projection kinds:

`index|sector|industry|source_category|item_type|event_type|time_bucket|
corpus_item|event`

Keep existing `ticker`, `source`, `fact`, `filing`, `section`,
`document_family`, `freshness`, and `scheduler_source` kinds.

Add relations such as:

`member_of|classified_as|published_by|occurred_as|bucketed_by|links_item|
covered_by`

Every id remains opaque and revision-bound. Aggregate nodes include count and
filter payload, not thousands of hidden child ids.

## Step 3: Add additive API surfaces

Extend `/graph/api/corpus/search` with the new facets and add bounded endpoints
only where clearer:

- `/graph/api/corpus/facets` — counts for the current filter set;
- `/graph/api/corpus/groups` — one paged aggregate level;
- `/graph/api/corpus/items/{id}` — safe detail/provenance;
- existing `/nodes/{id}/neighbors` expands one aggregate/item page.

All responses carry store revision, applied filters, page cursor, truncation,
and visible/total counts. A revision change invalidates the cursor with the
existing reset behavior.

Graph endpoints remain read-only and must not trigger embedding, refresh, model,
provider, or mutation work.

## Step 4: Enforce client and server bounds

- default result page: 50; maximum 100;
- visible graph target: 450; hard cap from configuration;
- inspector excerpt and metadata byte limits remain enforced server-side;
- aggregate/facet cache keyed by Store revision plus canonical filters;
- abort obsolete browser requests when filters change;
- debounce text search only; facet selection applies immediately;
- no unbounded client-side arrays of all results.

If a branch exceeds the cap, preserve the aggregate node/count and require a
filter or next page.

## Step 5: Measure representative scale

Seed at least:

- 600 securities;
- overlapping memberships and 11 sectors;
- 100,000 corpus metadata items across all source/item categories;
- mixed fresh/stale/error/indexing states;
- Chroma stubs sufficient to validate document detail without embedding 100,000
  test documents.

Offline targets:

- overview/facet p95 below 250 ms after warm schema initialization;
- filtered first page p95 below 300 ms;
- API response below configured element/byte limits;
- browser interaction remains responsive with 450 visible nodes;
- stage rail remains aligned through auto-fit, pan, zoom, and resize;
- scrubber input remains frame-coalesced and viewport-stable under a rapid input
  fixture;
- no full table/collection scan in query-plan assertions for indexed hot paths
  where SQLite exposes a stable plan.

Targets are acceptance goals to measure, not preclaimed results.

## Step 6: Verify accessibility and security

- synchronized semantic result table/list for canvas elements;
- keyboard selection, expansion, filters, reset, and inspector close;
- `aria-live="polite"` for loading/result/connection status;
- visible focus and WCAG 2.1 AA contrast;
- status not communicated by color alone;
- reduced-motion mode disables looping/animated graph effects;
- strict same-origin CSP, no third-party requests, no dynamic `innerHTML`;
- loopback-only/no-store/redaction behavior remains enforced.

## Testing

- Exercise every new group/facet/node/relation with revision-aware pagination.
- Prove aggregate count consistency against seeded canonical rows.
- Reject forged/expired ids, cursors, invalid filters, and excessive limits.
- Verify zero network/model/embedding/mutation calls during exploration.
- Measure API p95 against the seeded scale fixture.
- Run static UI contract checks plus implementation-time Playwright smoke under
  strict CSP.
- Retain regression checks for shared route placement, stage-rail viewport
  projection, instant/rAF-throttled scrubbing, freshness folding, and corpus
  label level-of-detail.
- Scan all responses for canary secrets, local paths, and unbounded text.

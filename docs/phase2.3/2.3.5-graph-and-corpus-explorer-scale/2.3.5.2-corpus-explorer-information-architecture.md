# 2.3.5.2 — Corpus Explorer Information Architecture

## Objective

Reorganize Corpus Explorer for a much larger, more diverse corpus. The default
view must explain coverage and freshness without drawing thousands of tickers or
documents.

## Design principle: aggregation first

The Phase 2.2 explorer can begin from sources/tickers/facts/filings. At Phase 2.3
scale, rendering that inventory directly becomes visual noise. The new landing
view starts with aggregate groups and expands on demand.

Phase 2.2 already establishes the first density reduction: freshness leaf nodes
are folded off the canvas into each ticker's worst-status ring and per-status
counts, while the synchronized list/table and inspector retain the complete
freshness inventory. Non-hub corpus labels also use zoom-based level-of-detail.
Phase 2.3 generalizes this proven fold/aggregate pattern; it must not restore the
freshness hairball or hide the folded records from accessible secondary views.

Recommended hierarchy:

```text
market universe
├── index (S&P 500, Nasdaq-100, overlap, off-index deep)
│   └── sector
│       └── security
│           └── source category
│               └── item/event type
│                   └── year/month
│                       └── corpus item
└── global sources
    └── central bank / treasury / economic agency / regulator
        └── item/event type
            └── year/month
                └── corpus item
```

This is a navigation projection, not a requirement that the underlying corpus be
stored as a graph. Users may enter through any facet rather than traverse the
entire hierarchy.

## Step 1: Add a persistent facet rail

Corpus mode exposes combinable filters:

- index/coverage tier;
- sector and industry;
- ticker/security;
- source category and specific source;
- item type and event type;
- form/exhibit where applicable;
- published/effective/as-of date range;
- freshness/indexing/error state;
- authority tier.

Filters show result counts before expansion. Provider names are available but do
not dominate the first navigation level.

Filter state is represented in the URL for refresh/back/forward/deep-link
behavior. Do not add cookies, analytics, or localStorage.

## Step 2: Separate inventory, canvas, and inspector roles

- **Inventory/results pane:** paged rows with title/ticker/type/source/date/status;
  keyboard-friendly and useful even without Cytoscape.
- **Canvas:** only selected aggregate groups, selected results, and their immediate
  relationships; never the full result set.
- **Inspector:** complete safe metadata, provenance origins, coverage/membership,
  freshness, indexing state, and bounded excerpt.

Selecting a result focuses/adds it to the canvas. Expanding a group adds one
bounded page and replaces/updates the aggregate count; it does not auto-expand
every descendant.

Source and ticker hubs remain labelled at overview zoom. Leaf labels appear only
after the existing zoom threshold or explicit selection, preserving the current
level-of-detail behavior as new node kinds are added.

## Step 3: Make time and source density understandable

Use time buckets and aggregate count nodes for dense branches. A security may show
summary badges such as:

- `SEC 14`, `news 86`, `market 252`, `official 3`;
- newest published date;
- stale/error/indexing-backlog indicators.

Badges are derived from aggregate endpoints, not individual hidden DOM nodes.
Status always uses text/icon/shape in addition to color.

## Step 4: Provide useful saved entry points without persistence

Add deterministic presets encoded as URL parameters:

- index coverage overview;
- financing and capital-markets events;
- latest company news;
- macro/policy releases;
- stale/error sources;
- indexing backlog;
- one ticker research view.

Presets are shortcuts over normal facets, not separate API behavior.

## Step 5: Preserve the visual system

Keep the Phase 2.2 TraceAlchemy Telemetry palette, typography, graph canvas,
provenance beam, inspector, reduced-motion behavior, table fallback, strict CSP,
and loopback-only model. Add no frontend framework or build chain.

At narrower widths, the facet rail and inspector become independently accessible
drawers/bottom sheets. The result list remains usable with the canvas collapsed.

## Testing

- Combine index, sector, ticker, source, type, and date filters and preserve them
  through a URL reload.
- Navigate inventory entirely by keyboard and select/focus an item.
- Use table/list fallback with Cytoscape unavailable.
- Expand one aggregate page without exceeding the visible-node cap.
- Prove folded freshness leaves remain available in the list/table and ticker
  inspector with the correct worst-status ring/counts.
- Prove source/ticker hub labels remain visible while dense leaf labels obey
  zoom-based level-of-detail.
- Show zero/empty/error/stale/indexing states with clear actions.
- Verify reduced motion, contrast, focus visibility, accessible names/status, and
  a 1280px layout.

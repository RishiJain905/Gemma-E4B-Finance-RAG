# 2.3.5.1 — Source-Aware Live Trace Contract

## Objective

Extend Live Trace to explain how the expanded source set contributed to an
answer without creating provider-specific graph schemas or turning ingestion
runs into query traces.

## Scope boundary

Live Trace continues to represent one executed query:

```text
question -> plan/subquery -> retrieval/tool -> evidence -> source -> answer/citation
```

It does not visualize scheduler execution. Refresh/corpus health belongs in
Corpus Explorer. A query-triggered bounded refresh may appear as the existing tool
node with a safe result summary, but not as hundreds of ingestion item nodes.

## Phase 2.2 baseline to preserve

The post-2.2.7 defect fixes make the legacy intent parse the executed routing
stage. It therefore uses the shared query-scoped `stage:route` node id, while its
reader-facing label may remain `Intent`. Legacy tool `routed_to` edges without a
subquery originate from that same node. Phase 2.3 must extend this route node
rather than reintroduce a separate `stage:intent` identity or dangling tool edge.

Adaptive-to-legacy fallback retains the same route identity and marks it
`fallback` with a bounded reason. The UI's stage classifier continues to place
`Intent`, `Route`, and composed route/intent labels in the ROUTE column.

## Step 1: Extend allowlisted evidence metadata

Add safe fields to evidence/source nodes:

- canonical `security_id` and ticker;
- index memberships and coverage tier;
- source category, source name, and authority tier;
- item type and optional event type;
- provider/publisher distinction;
- filing form/item/exhibit or observation/event date where relevant;
- published/effective/as-of/accessed timestamps;
- freshness and normalization version;
- corpus item id/document family id when already safe and opaque.

Never include API keys, request headers, raw provider payloads, complete article
text, local paths, or unbounded metadata.

## Step 2: Keep node kinds source-independent

Reuse existing `evidence`, `source`, `tool`, `citation`, and answer nodes. Add
subtypes in metadata/style rather than node kinds such as `finnhub_news` or
`massive_price`.

Structured observations reached through deterministic tools remain tool/fact
evidence. Narrative records remain document evidence. Classified events may add
an `event` subtype but must still resolve to one or more exact evidence ledger
ids.

## Step 3: Show fallback and corroboration truthfully

When retrieval uses several sources:

- each returned evidence node links to its actual source;
- primary and secondary/corroborating evidence are distinguishable;
- duplicate records removed before context appear as bounded dropped/deduped
  stage counts, not fabricated evidence nodes;
- unavailable/rate-limited sources appear only if the query actually attempted a
  runtime source/tool path;
- a scheduler-time source failure is not retroactively inserted into a query.

The provenance beam continues to highlight the exact evidence-to-citation path.
The inspector adds source category, authority, event/item type, and date semantics.

## Step 4: Version compatibly

Add fields through the existing graph schema allowlist. Bump the schema version
only if required by a changed enum/required field. Phase 2.2 golden traces remain
readable; new golden fixtures cover mixed SEC/news/macro/market evidence.

Observer-disabled responses remain compatible and graph publishing remains
non-blocking/fail-soft.

## Testing

- Build a mixed trace with SEC financing evidence, company news, a structured
  market observation, and a macro release.
- Resolve every displayed source/evidence/citation to the final evidence ledger.
- Prove provider/publisher and primary/secondary labels remain distinct.
- Prove deduped context does not create duplicate evidence nodes.
- Exercise a legacy tool path and prove all `routed_to` edges resolve to the
  shared `stage:route` node.
- Exercise adaptive-to-legacy fallback and preserve the route node's fallback
  status/reason without creating a duplicate routing node.
- Redact canary keys, headers, payloads, local paths, and excessive text.
- Prove observer-disabled and observer-failure paths do not change answers.
- Retain the existing publish p95 below 2 ms offline gate.

## Verification Checklist

- [ ] Live Trace shows exact source category, item/event type, authority, and dates
- [ ] No provider-specific graph node vocabulary is introduced
- [ ] Structured and narrative evidence use their correct executed paths
- [ ] Ingestion-only events never pollute query traces
- [ ] Legacy and fallback tool edges retain the shared, non-dangling route node
- [ ] The provenance beam resolves to the supplied evidence ledger
- [ ] Redaction, loopback, bounded-memory, and non-interference guarantees hold

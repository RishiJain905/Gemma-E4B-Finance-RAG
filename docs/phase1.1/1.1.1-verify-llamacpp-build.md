# 1.1.1 — Verify the llama.cpp Build (AMD RDNA3)

## Objective

Confirm that your custom `atomic-llama-cpp-turboquant` build for AMD RDNA3 (gfx1101) is complete and the `llama-server.exe` binary exists. This is the foundation — if the build is broken, nothing downstream works.

## Your Environment

| Component | Value |
|-----------|-------|
| OS | Windows |
| GPU | AMD RDNA3 (gfx1101) |
| Build project | `atomic-llama-cpp-turboquant` |
| Build directory | `F:\Personal\TQ-Optimizer-Test\atomic-llama-cpp-turboquant\build-rdna3-gfx1101` |
| Server binary | `bin\llama-server.exe` |

## Why This Matters

Your setup is a custom ROCm/HIP build of llama.cpp specifically compiled for AMD RDNA3 GPUs. Unlike a generic llama.cpp binary, this build:

1. **Targets gfx1101** — instruction set optimized for your exact GPU architecture
2. **Supports ROCm** — AMD's GPU compute platform, required for acceleration
3. **Includes turbo4** — an AMD-specific 4-bit cache quantization format that improves memory bandwidth
4. **MTP support** — Multi-Token Prediction speculative decoding requires a build that includes the draft model pipeline

A generic llama.cpp build downloaded from somewhere else will NOT have these optimizations and will underperform or fail entirely on your hardware.

## What We Need to Verify

### 1. Binary Exists

```powershell
Get-Item "F:\Personal\TQ-Optimizer-Test\atomic-llama-cpp-turboquant\build-rdna3-gfx1101\bin\llama-server.exe"
```

Expected: File info displays with size > 50 MB (Release build with ROCm support).

### 2. Build Version

```powershell
# Run with --version to see build info
& "F:\Personal\TQ-Optimizer-Test\atomic-llama-cpp-turboquant\build-rdna3-gfx1101\bin\llama-server.exe" --version
```

Look for:
- **Build target** — should mention `gfx1101` or `hip` or `ROCm`
- **GPU backend** — `HIP` (AMD's ROCm interface)
- **Flash attention** — should be available

### 3. Quick Sanity Check

```powershell
# Show help to confirm it starts without crashing
& "F:\Personal\TQ-Optimizer-Test\atomic-llama-cpp-turboquant\build-rdna3-gfx1101\bin\llama-server.exe" --help | Select-Object -First 20
```

### 4. Check GPU Driver Compatibility

```powershell
# Check AMD driver version
Get-CimInstance Win32_VideoController | Where-Object { $_.Name -like "*AMD*" } | Select-Object Name, DriverVersion, AdapterRAM
```

Expected: Adrenalin 24.x+ driver with ROCm support. If driver is too old, the HIP backend may fail silently.

### 5. Confirm ROCm DLLs Are Accessible

The build depends on AMD ROCm runtime DLLs. If the `.exe` fails to start due to missing DLLs:

```powershell
# Try running the server briefly to check for DLL errors
# If it fails, check the error message for missing .dll files
& "F:\Personal\TQ-Optimizer-Test\atomic-llama-cpp-turboquant\build-rdna3-gfx1101\bin\llama-server.exe" --version
# If you see "The code execution cannot proceed because XYZ.dll was not found",
# ensure ROCm binaries are in your PATH
```

## What Could Go Wrong

| Problem | Likely Cause | Fix |
|---------|-------------|------|
| `llama-server.exe not found` | Build incomplete | Re-run the CMake build: `cd build-rdna3-gfx1101 && cmake --build . --config Release` |
| `HIP is not available` | ROCm not installed or PATH missing | Install AMD ROCm for Windows. Add ROCm `bin` directory to PATH. |
| `gfx1101: unknown target` | Wrong build config | Ensure cmake was configured with `-DAMDGPU_TARGETS=gfx1101` or `-DLLAMA_HIP_UMA=ON` |
| Missing DLL error at startup | ROCm runtime not in PATH | Check `$env:Path` contains the ROCm bin directory. Typically `C:\Program Files\AMD\ROCm\*\bin` |
| Driver too old | AMD Adrenalin < 24.x | Update to latest Adrenalin drivers from amd.com |
| Server starts but GPU layers don't offload | HIP backend not fully initialized | Check server logs for "offloading to GPU" messages. May need to reboot after driver install |

# 1.1.3 — Start llama-server with Optimal Configuration

## Objective

Launch `llama-server` with parameters tuned specifically for the TraceAlchemy model on your Mac Mini M4 (32GB), balancing inference quality, memory usage, and context length.

## Why This Matters

The default `llama-server` flags are conservative — they'll work, but they won't give you the best performance for this model. The right configuration doubles your usable context, halves latency, and prevents out-of-memory crashes during long document processing (which is the whole point of this RAG system).

The key decisions here are:
- **Context size** — how much text the model can "see" at once. More is better for full filings, but costs memory.
- **GPU offloading** — how many layers run on the GPU vs. CPU. The M4's unified memory is fast, but 32 GB is shared between system and GPU.
- **Flash attention** — a memory optimization that's nearly free in quality. Always on.

## The Command

```bash
llama-server \
  -m ~/models/tracealchemy/TraceAlchemy-Gemma-4-E4B-Finance-IT.gguf \
  --port 8080 \
  --host 127.0.0.1 \
  --ctx-size 32768 \
  --n-gpu-layers 99 \
  --rope-scaling none \
  --flash-attn 1 \
  --parallel 1 \
  --cont-batching 1
```

## Parameter Breakdown

### `-m` — Model Path
The absolute path to your GGUF file from Task 1.1.2. Use the full path to avoid ambiguity when running from different directories.

### `--port 8080` — Server Port
`8080` is the standard port for local LLM servers. The middleware (Phase 1.5) will point to `http://127.0.0.1:8080`.

### `--host 127.0.0.1` — Bind Address
Bind to localhost only — the server is not exposed to your local network. This is a security best practice for local model serving. Only processes on your machine can reach it.

### `--ctx-size 32768` — Context Window
The TraceAlchemy model supports up to 128K native context. Setting this to **32,768** tokens is a sweet spot:

| Context | Memory Usage | Can Fit | Best For |
|---------|-------------|---------|----------|
| 8,192 | ~4 GB | A few news articles | Quick Q&A |
| **32,768** | **~8 GB** | **Full SEC 10-Q or 10-K section** | **General use** |
| 65,536 | ~14 GB | Entire 10-K filing | Heavy analysis |
| 131,072 | ~24 GB | Multiple filings + analysis | Max context |

32K is the recommended default. You can increase it per-query from the middleware for specific deep-read requests.

### `--n-gpu-layers 99` — GPU Acceleration
The Gemma 4 E4B has approximately 48 layers in its architecture. Setting `99` offloads **all** of them to the GPU (Metal on M4). The value is intentionally higher than the layer count to be safe across GGUF quant variations.

If you experience memory pressure (swap usage), reduce to `--n-gpu-layers 32` to offload only the compute-heavy layers and keep embeddings on CPU.

### `--rope-scaling none`
No RoPE scaling needed — we're running at native context, not extending beyond the trained context window.

### `--flash-attn 1`
Enables flash attention — a memory-efficient attention algorithm. This is **strongly recommended** for any context over 8K. Without it, attention memory scales quadratically with context length. With it, memory scales linearly. On the M4, this is the difference between fitting 32K context and crashing.

### `--parallel 1`
One concurrent request slot. This is a single-user system — you don't need parallel request handling. Keeping it at 1 reduces memory overhead. Can be increased to 2-4 if you want to batch queries from the middleware.

### `--cont-batching 1`
Enables continuous batching — the server can queue incoming requests while processing and start on the next one immediately after finishing, rather than draining the batch fully before accepting new work.

## Expected Output

When the server starts successfully, you should see output similar to:

```
main: model loaded
main: model size = 9.60 GB
main: offloading 48 layers to GPU
main: offloading 1 embedding layer to GPU
main: offloaded 49/49 layers to GPU
main: context size = 32768
main: flash attention = 1
main: server is listening on 127.0.0.1:8080
```

## What Could Go Wrong

| Problem | Likely Cause | Fix |
|---------|-------------|------|
| `GGML_ASSERT: ... failed` | Context size too large for available memory | Reduce `--ctx-size` to 16384 |
| `cannot load model` | Model path wrong or file corrupt | Verify path from Task 1.1.2, re-download GGUF |
| Port already in use | Another process on :8080 | Kill it (`lsof -ti :8080 \| xargs kill`) or use `--port 8081` |
| Server starts but hangs | Insufficient system memory close swap | Reduce `--n-gpu-layers` or `--ctx-size`, check Activity Monitor |
| Metal errors on M4 | Outdated llama.cpp build | Rebuild with latest source: `git pull && cmake --build . --config Release` |

## Running in Background

Keep the server running in the background so you can use the terminal for other tasks:

```bash
# Using nohup
nohup llama-server \
  -m ~/models/tracealchemy/TraceAlchemy-Gemma-4-E4B-Finance-IT.gguf \
  --port 8080 --host 127.0.0.1 --ctx-size 32768 \
  --n-gpu-layers 99 --flash-attn 1 \
  --parallel 1 --cont-batching 1 \
  > ~/models/tracealchemy/server.log 2>&1 &

# Check it's running
tail -f ~/models/tracealchemy/server.log
```

**Note:** A wrapper script will be created in Task 1.1.5 to handle this cleanly.

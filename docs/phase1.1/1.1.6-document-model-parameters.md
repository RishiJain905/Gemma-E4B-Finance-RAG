# 1.1.6 — Document Model Parameters

## Objective

Record the exact configuration and capabilities of the TraceAlchemy model as served by `llama-server`, creating a reference document that the middleware (Phase 1.5) and future components can use to configure their requests correctly.

## Why This Matters

The middleware doesn't know anything about the model's capabilities by default — it needs to be told:
- What endpoint to hit
- What context size is available
- What the model's max output should be
- What sampling parameters work well
- Whether it supports embeddings

Without this documented, the middleware developer has to guess or read the model's Hugging Face page. With it documented in your own terms (after testing), every component aligns.

## Model Configuration Record

Create a config file at `configs/model.yaml` that serves as the single source of truth:

```yaml
# configs/model.yaml
# TraceAlchemy Model Configuration
# Used by: middleware, ingestion scripts, embedding service

model:
  name: "TraceAlchemy-Gemma-4-E4B-Finance-IT"
  id: "tracealchemy"
  backend: "llama-server"
  base_url: "http://127.0.0.1:8080"

  # Architecture
  family: "Gemma 4 E4B"
  architecture: "Mixture-of-Experts (MoE)"
  parameters_total: "~9B"
  parameters_active: "~2.6B"
  quantization: "GGUF Q4_K_M"  # Update to match your actual quant

  # Context & Limits
  max_context: 32768
  max_tokens_default: 2048
  max_tokens_max: 8192
  supported_modes:
    - chat
    - completion
    - embedding

  # API Endpoints
  endpoints:
    chat_completions: "/v1/chat/completions"
    completions: "/v1/completions"
    embeddings: "/v1/embeddings"

  # Default Sampling Parameters
  # These are starting points — adjust based on your experience
  defaults:
    temperature: 0.7
    top_p: 0.95
    top_k: 40
    repeat_penalty: 1.1
    frequency_penalty: 0.0
    presence_penalty: 0.0

  # Recommended Parameter Ranges by Task
  tasks:
    fact_extraction:
      description: "Parsing SEC filings into structured data"
      temperature: 0.1
      top_p: 0.9
      repeat_penalty: 1.0
      max_tokens: 1024
    general_qa:
      description: "Answering user queries with RAG context"
      temperature: 0.7
      top_p: 0.95
      max_tokens: 512
    analysis:
      description: "Deep financial analysis and reasoning"
      temperature: 0.5
      top_p: 0.95
      max_tokens: 2048

  # Embedding
  embedding:
    enabled: true
    default_model: "tracealchemy"
    dimension: 0  # Will be filled after Task 1.1.7
    normalize: true
```

### Why Per-Task Parameters Matter

Different tasks need different model behavior:

- **Fact extraction** (low temp, 0.1): You want deterministic, consistent output when parsing SEC filings into structured facts. Creativity would introduce hallucinated data.
- **General Q&A** (medium temp, 0.7): Balanced creativity and determinism for answering questions with RAG context. The retrieved facts ground the answer; some temperature allows natural language variation.
- **Deep analysis** (medium-low temp, 0.5): Analytical writing benefits from some creativity but shouldn't drift into speculation. Lower temperature keeps reasoning tight.

## What to Record in Practice

When you run the model, update the following:

1. **Actual tokens per second** — run `1.1.4 Test 4` and note the rate
2. **Memory usage** — check in Activity Monitor while running
3. **Stable context size** — what's the max you've tested without issues?
4. **Quantization type** — what GGUF quant are you using? (Q4_K_M, Q5_K_M, Q8_0, etc.)
5. **Model behavior quirks** — does it repeat certain phrases? Does it refuse certain types of questions?

# 1.1.7 — Verify Embedding Endpoint

## Objective

Confirm that `llama-server`'s embedding endpoint is functional and produces consistent, usable embeddings — a prerequisite for ChromaDB (Phase 1.2) which needs an embedding function to store and retrieve vector representations of documents.

## Why This Matters

ChromaDB doesn't generate embeddings itself. You give it a function — a "what to call to turn text into vectors" — and it calls that function every time you add or search documents. For this project, that function points at your local `llama-server`'s embedding endpoint.

If embeddings are:
- **Broken** — nothing goes into ChromaDB, retrieval returns empty
- **Wrong dimension** — vectors don't match what ChromaDB expects, you get silent errors
- **Inconsistent** — same text produces different vectors on different calls, semantic search is useless

This task catches those problems before ChromaDB is involved.

## Test the Embedding Endpoint

### Basic Embedding Request

```bash
curl http://127.0.0.1:8080/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{
    "input": "NVIDIA reported record datacenter revenue of $26 billion in Q1 2026, driven by demand for Blackwell GPUs.",
    "model": "tracealchemy"
  }'
```

**Expected response:**
```json
{
  "object": "list",
  "data": [
    {
      "object": "embedding",
      "index": 0,
      "embedding": [-0.0123, 0.0456, 0.0789, ...]  # ~2048 or ~4096 floats
    }
  ],
  "model": "tracealchemy",
  "usage": {
    "prompt_tokens": 23,
    "total_tokens": 23
  }
}
```

### What to Check

1. **Dimension** — count the number of floats in the embedding array
   ```bash
   curl -s http://127.0.0.1:8080/v1/embeddings \
     -H "Content-Type: application/json" \
     -d '{"input": "test", "model": "tracealchemy"}' \
     | jq '.data[0].embedding | length'
   ```
   - Common values: 2048, 4096
   - **Record this number** — it's needed when configuring ChromaDB

2. **Consistency** — run the same input twice
   ```bash
   # Run twice and compare
   curl -s ... -d '{"input": "NVIDIA revenue growth", "model": "tracealchemy"}' | jq '.data[0].embedding' > /tmp/embed1.json
   curl -s ... -d '{"input": "NVIDIA revenue growth", "model": "tracealchemy"}' | jq '.data[0].embedding' > /tmp/embed2.json
   diff /tmp/embed1.json /tmp/embed2.json
   ```
   - **Identical vectors** = deterministic embeddings (good for caching)
   - **Slightly different** = stochastic embeddings (needs seed fixing, or live with it — ChromaDB handles this fine for search, just means no caching)

3. **Semantic Similarity** — similar texts should produce similar vectors
   ```bash
   # Compare two related texts using cosine similarity
   python3 -c "
   import json, math, requests
   
   def get_embedding(text):
       r = requests.post('http://127.0.0.1:8080/v1/embeddings',
           json={'input': text, 'model': 'tracealchemy'})
       return r.json()['data'][0]['embedding']
   
   def cosine_sim(a, b):
       dot = sum(x*y for x,y in zip(a,b))
       na = math.sqrt(sum(x*x for x in a))
       nb = math.sqrt(sum(x*x for x in b))
       return dot / (na * nb)
   
   texts = [
       'NVIDIA reported strong datacenter revenue growth from AI chips',
       'AMD is gaining market share in the GPU market for AI workloads',
       'The Federal Reserve kept interest rates unchanged at 4.5%'
   ]
   
   embs = [get_embedding(t) for t in texts]
   
   print('Related texts:', cosine_sim(embs[0], embs[1]))
   print('Unrelated texts:', cosine_sim(embs[0], embs[2]))
   print('Same text:', cosine_sim(embs[0], embs[0]))
   "
   ```
   - `Same text: ~1.0` (identical = perfect similarity)
   - `Related texts: > 0.7` (NVDA and AMD are both GPU/AI)
   - `Unrelated texts: < 0.5` (NVDA and Fed policy are different topics)
   
   If the similarity scores seem flat (all 0.9+ or all 0.1-), the embeddings may not be useful for semantic search.

4. **Batch Embedding** (optional but good to know)
   ```bash
   curl http://127.0.0.1:8080/v1/embeddings \
     -H "Content-Type: application/json" \
     -d '{
       "input": [
         "NVIDIA datacenter revenue grew 42% YoY",
         "AMD announced new MI400 AI accelerator",
         "Intel foundry services reported operating loss"
       ],
       "model": "tracealchemy"
     }'
   ```
   - Should return 3 embedding vectors in the `data` array
   - This is how you'll embed multiple documents efficiently during ingestion

## What Happens If...

| Problem | Impact | Fix |
|---------|--------|-----|
| Wrong dimension set in ChromaDB | ChromaDB throws dimension mismatch errors | Update `dimension` in config and re-create the collection |
| Embeddings are low quality | Semantic search returns irrelevant results | Try a different model layer for embeddings (e.g., use the last hidden state instead of the output) |
| Embedding endpoint returns error | Nothing can be stored in ChromaDB | Check server logs, ensure `llama-server` supports the embeddings endpoint (it's enabled by default in recent builds) |
| `jq` not found | Can't parse JSON | `brew install jq` (macOS) or `apt install jq` (Linux) |

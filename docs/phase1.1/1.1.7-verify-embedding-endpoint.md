# 1.1.7 — Verify Embedding Endpoint

## Objective

Confirm that `llama-server`'s embedding endpoint is functional and produces consistent, usable embeddings — a prerequisite for ChromaDB (Phase 1.2) which needs an embedding function to store and retrieve vector representations of documents.

Since you launched with `--embeddings` flag, this endpoint is already enabled.

## Why This Matters

ChromaDB doesn't generate embeddings itself. You give it a function — "what to call to turn text into vectors" — and it calls that function every time you add or search documents. For this project, that function points at your local `llama-server` on port **8087**.

If embeddings are:
- **Broken** — nothing goes into ChromaDB, retrieval returns empty
- **Wrong dimension** — vectors don't match what ChromaDB expects, you get silent errors
- **Inconsistent** — same text produces different vectors on different calls, semantic search is unreliable

This task catches those problems before ChromaDB is involved.

## Test the Embedding Endpoint

### Basic Embedding Request

```powershell
curl http://127.0.0.1:8087/v1/embeddings `
  -H "Content-Type: application/json" `
  -d '{"input": "NVIDIA reported record datacenter revenue of $26 billion in Q1 2026, driven by demand for Blackwell GPUs.", "model": "tracealchemy"}'
```

**Expected response structure:**
```json
{
  "object": "list",
  "data": [{
    "object": "embedding",
    "index": 0,
    "embedding": [-0.0123, 0.0456, 0.0789, ...]
  }],
  "model": "tracealchemy",
  "usage": {
    "prompt_tokens": 23,
    "total_tokens": 23
  }
}
```

### 1. Get the Embedding Dimension

This is the most important number — you need it for ChromaDB setup:

```powershell
curl -s http://127.0.0.1:8087/v1/embeddings `
  -H "Content-Type: application/json" `
  -d '{"input": "test", "model": "tracealchemy"}' `
  | python -c "import sys,json; print(len(json.load(sys.stdin)['data'][0]['embedding']))"
```

**Likely value:** 2048 (Gemma 4 E4B hidden dimension). Could also be 4096 depending on the model architecture.

**Record this number** and update `configs/model.yaml`:
```yaml
embedding:
  dimension: 2048  # ← Replace 0 with actual value
```

### 2. Check Consistency

Run the same input twice and compare:

```powershell
# First call
curl -s http://127.0.0.1:8087/v1/embeddings `
  -H "Content-Type: application/json" `
  -d '{"input": "NVIDIA revenue growth", "model": "tracealchemy"}' `
  | python -c "import sys,json; f=open('embed1.json','w'); json.dump(json.load(sys.stdin)['data'][0]['embedding'], f); f.close()"

# Second call  
curl -s http://127.0.0.1:8087/v1/embeddings `
  -H "Content-Type: application/json" `
  -d '{"input": "NVIDIA revenue growth", "model": "tracealchemy"}' `
  | python -c "import sys,json; f=open('embed2.json','w'); json.dump(json.load(sys.stdin)['data'][0]['embedding'], f); f.close()"

# Compare
python -c "
import json
a = json.load(open('embed1.json'))
b = json.load(open('embed2.json'))
print('Identical:', a == b)
print('Max diff:', max(abs(x-y) for x,y in zip(a,b)))
"
```

- **Identical vectors** (`Max diff: 0.0`) = deterministic embeddings (good for caching)
- **Slightly different** = stochastic embeddings (ChromaDB handles this fine, just means no caching)

### 3. Semantic Similarity Test

Similar texts should produce similar vectors:

```powershell
python -c "
import json, math, requests

def get_embedding(text):
    r = requests.post('http://127.0.0.1:8087/v1/embeddings',
        json={'input': text, 'model': 'tracealchemy'})
    return r.json()['data'][0]['embedding']

def cosine_sim(a, b):
    dot = sum(x*y for x,y in zip(a,b))
    na = math.sqrt(sum(x*x for x in a))
    nb = math.sqrt(sum(x*x for x in b))
    return dot / (na * nb)

texts = [
    'NVIDIA reported strong datacenter revenue growth from AI chips',
    'AMD is gaining market share in the GPU market for AI workloads',
    'The Federal Reserve kept interest rates unchanged at 4.5%'
]

embs = [get_embedding(t) for t in texts]

print(f'Same text:        {cosine_sim(embs[0], embs[0]):.4f}')  # Should be ~1.0
print(f'Related (NVDA/AMD): {cosine_sim(embs[0], embs[1]):.4f}')  # Should be >0.7
print(f'Unrelated (NVDA/Fed): {cosine_sim(embs[0], embs[2]):.4f}')  # Should be <0.5
"
```

**If similarity scores are flat** (all 0.9+ or all 0.1-), the embeddings may not be useful for semantic search. This is rare with Q8_0 quantization but worth checking.

### 4. Batch Embedding

Ingestion pipelines often send multiple texts at once:

```powershell
curl http://127.0.0.1:8087/v1/embeddings `
  -H "Content-Type: application/json" `
  -d '{
    "input": [
      "NVIDIA datacenter revenue grew 42% YoY",
      "AMD announced new MI400 AI accelerator",
      "Intel foundry services reported operating loss"
    ],
    "model": "tracealchemy"
  }'
```

Should return 3 embedding vectors in the `data` array. This is how you'll embed multiple documents efficiently during ingestion.

## What Could Go Wrong

| Problem | Impact | Fix |
|---------|--------|------|
| 404 on `/v1/embeddings` | Endpoint not enabled | Restart with `--embeddings` flag |
| Wrong dimension set in ChromaDB | ChromaDB throws dimension mismatch | Update `dimension` in config, re-create the collection |
| Embeddings are low quality | Semantic search returns irrelevant results | Try different `-ctk`/`-ctv` values or switch to a non-quantized cache |
| `python` not found | Can't run similarity test | Use `python3` or `py` depending on your install. Or install Python |
| Embedding of empty string fails | Server may not handle empty inputs | Always send meaningful text. Avoid `""` and `"test"` — use a real sentence |

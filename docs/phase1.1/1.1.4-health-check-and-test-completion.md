# 1.1.4 — Health Check & Test Completion

## Objective

Verify that `llama-server` is responding correctly on port **8087** by sending test prompts to both the completions and chat completions endpoints, and confirm the model produces coherent financial reasoning.

## Why This Matters

A running server doesn't mean a working server. The model could be loaded but producing garbage output, returning errors, or silently failing on certain endpoints. You need to confirm:

1. The API responds with valid JSON
2. The model outputs are coherent (finance-relevant, not gibberish)
3. Both endpoint types work (the middleware uses chat completions)
4. MTP speculative decoding is accelerating inference as expected

This is your baseline test — if these pass, the model serving layer is solid.

## Endpoint Reference

`llama-server` exposes an OpenAI-compatible API. Your instance runs on **port 8087**.

| Endpoint | Purpose | Used By |
|----------|---------|---------|
| `/v1/completions` | Raw text completion | Testing, direct model interaction |
| `/v1/chat/completions` | Chat-style with messages | Middleware (Phase 1.5) |
| `/v1/embeddings` | Generate embeddings | ChromaDB (Phase 1.2) |

## Test 1: Basic Completion

```powershell
curl http://127.0.0.1:8087/v1/completions `
  -H "Content-Type: application/json" `
  -d '{"prompt": "What is the P/E ratio and how is it calculated?", "max_tokens": 150, "temperature": 0.7}'
```

**Expected output structure:**
```json
{
  "choices": [{
    "text": "The P/E (Price-to-Earnings) ratio is a valuation metric...",
    "finish_reason": "stop"
  }]
}
```

**Check for:**
- `"finish_reason": "stop"` — completed naturally
- Response contains actual financial reasoning about P/E ratios
- Token usage is reported

## Test 4: Multi-Turn Context

Test that the model maintains context across a conversation:

```powershell
# Turn 1
curl -s http://127.0.0.1:8087/v1/chat/completions `
  -H "Content-Type: application/json" `
  -d '{"model": "tracealchemy", "messages": [{"role": "system", "content": "You are a financial analyst."}, {"role": "user", "content": "What sector is showing the most growth momentum right now?"}], "max_tokens": 150}' `
  | python -c "import sys,json; print(json.load(sys.stdin)['choices'][0]['message']['content'])"

# Turn 2 — Reference the previous answer
curl -s http://127.0.0.1:8087/v1/chat/completions `
  -H "Content-Type: application/json" `
  -d '{"model": "tracealchemy", "messages": [{"role": "system", "content": "You are a financial analyst."}, {"role": "user", "content": "What sector is showing the most growth momentum right now?"}, {"role": "assistant", "content": "The semiconductor sector, particularly companies involved in AI infrastructure like NVIDIA and AMD..."}, {"role": "user", "content": "What are the risks to that outlook?"}], "max_tokens": 150}' `
  | python -c "import sys,json; print(json.load(sys.stdin)['choices'][0]['message']['content'])"
```

**Check for:**
- Follow-up answer is relevant to the previous context
- Risks mentioned are specific to the previously named sector

## Performance Baseline

Record these numbers — they're especially interesting with MTP speculative decoding:

```powershell
# Time a simple query
Measure-Command {
  curl -s http://127.0.0.1:8087/v1/chat/completions `
    -H "Content-Type: application/json" `
    -d '{"model": "tracealchemy", "messages": [{"role": "user", "content": "What is a P/E ratio?"}], "max_tokens": 100}' | Out-Null
}
```

| Metric | Expected (RDNA3 + MTP) | Notes |
|--------|------------------------|-------|
| Time to first token | < 3s | Model loads into VRAM first time |
| Tokens per second | 25-50 t/s | MTP speculative decoding provides ~2-3x speedup over normal decoding |
| Full 150-token response | ~3-6s | Should be noticeably faster than non-MTP |

## What Could Go Wrong

| Problem | Likely Cause | Fix |
|---------|-------------|------|
| `curl: (7) Connection refused` | Server not running or wrong port | Check port is 8087. Start the server (Task 1.1.3). |
| Empty response / timeout | 128K context + Q8_0 may be slow first time | Wait longer, or restart with `-c 65536` to test |
| Gibberish output | Model loaded incorrectly or wrong GGUF | Check GGUF integrity (Task 1.1.2) |
| `finish_reason: "length"` | Response cut off at max_tokens | Increase `max_tokens` in the request |
| Very slow responses (MTP not working) | Draft model rejection rate too high | Check logs for `mtp_accepted/mtp_rejected` ratio. If >50% rejected, lower `--draft-block-size` to 2 |
| `curl not recognized` | curl not installed on Windows | Use `winget install curl` or download from https://curl.se/windows/ |

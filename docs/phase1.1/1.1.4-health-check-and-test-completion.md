# 1.1.4 — Health Check & Test Completion

## Objective

Verify that `llama-server` is responding correctly by sending test prompts to both the **completions** and **chat completions** endpoints, and confirm the model produces coherent financial reasoning.

## Why This Matters

A running server doesn't mean a working server. The model could be loaded but producing garbage output, returning errors, or silently failing on certain endpoints. You need to confirm:
1. The API responds with valid JSON
2. The model outputs are coherent (finance-relevant, not gibberish)
3. Both endpoint types work (the middleware uses chat completions)
4. Latency is acceptable

This is your baseline test — if these pass, the model serving layer is solid and any future issues are in the data or middleware layers.

## Endpoint Reference

`llama-server` exposes an OpenAI-compatible API. The two endpoints you'll use:

| Endpoint | Purpose | Used By |
|----------|---------|---------|
| `/v1/completions` | Raw text completion | Testing, direct model interaction |
| `/v1/chat/completions` | Chat-style with messages | Middleware (Phase 1.5) |
| `/v1/embeddings` | Generate embeddings | ChromaDB (Phase 1.2) |

## Test 1: Basic Completion

Send a simple prompt to the raw completions endpoint:

```bash
curl http://127.0.0.1:8080/v1/completions \
  -H "Content-Type: application/json" \
  -d '{
    "prompt": "What is the P/E ratio and how is it calculated?",
    "max_tokens": 150,
    "temperature": 0.7
  }'
```

**Expected output structure:**
```json
{
  "choices": [
    {
      "text": "The P/E (Price-to-Earnings) ratio is a valuation metric...",
      "index": 0,
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 12,
    "completion_tokens": 87,
    "total_tokens": 99
  }
}
```

**Check for:**
- `"finish_reason": "stop"` — model completed naturally (not truncated)
- Response contains actual financial reasoning about P/E ratios
- Token usage is reported

## Test 2: Chat Completion

This is the endpoint the middleware will use. Include system + user messages:

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "tracealchemy",
    "messages": [
      {"role": "system", "content": "You are a financial analyst specializing in equity research. Answer clearly and with specific data when possible."},
      {"role": "user", "content": "Explain the difference between trailing P/E and forward P/E. Which one is more useful for value investing?"}
    ],
    "max_tokens": 200,
    "temperature": 0.7
  }'
```

**Expected output structure:**
```json
{
  "choices": [
    {
      "message": {
        "role": "assistant",
        "content": "Trailing P/E uses the past 12 months of actual earnings..."
      },
      "finish_reason": "stop"
    }
  ],
  "usage": {
    "prompt_tokens": 45,
    "completion_tokens": 120,
    "total_tokens": 165
  }
}
```

**Check for:**
- Valid JSON response with `choices[0].message.content`
- Financially coherent answer (correct definitions, meaningful distinction)
- Model stays in character as a financial analyst

## Test 3: Finance-Specific Prompt

Test with a prompt that requires domain knowledge your finetune should excel at:

```bash
curl http://127.0.0.1:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "tracealchemy",
    "messages": [
      {"role": "system", "content": "You are a financial analyst."},
      {"role": "user", "content": "What key metrics should I look at when evaluating a semiconductor company like NVIDIA? List the top 5 and explain why each matters."}
    ],
    "max_tokens": 300,
    "temperature": 0.7
  }'
```

**What to look for:**
- Specific, relevant metrics (datacenter revenue growth, gross margins, CUDA ecosystem moat, supply chain depth, R&D spend)
- Not generic — the finetune should produce more nuanced answers than a base model
- Reasonable formatting (numbered lists, clear explanations)

## Test 4: Multi-Turn Conversation

Test that the model maintains context across a short conversation:

```bash
# Turn 1
curl -s http://127.0.0.1:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "tracealchemy",
    "messages": [
      {"role": "system", "content": "You are a financial analyst."},
      {"role": "user", "content": "What sector is showing the most growth momentum right now?"}
    ],
    "max_tokens": 150,
    "temperature": 0.7
  }' | jq '.choices[0].message.content'
```

```bash
# Turn 2 — follow-up referencing the previous answer
curl -s http://127.0.0.1:8080/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "tracealchemy",
    "messages": [
      {"role": "system", "content": "You are a financial analyst."},
      {"role": "user", "content": "What sector is showing the most growth momentum right now?"},
      {"role": "assistant", "content": "The semiconductor sector, particularly companies involved in AI infrastructure like NVIDIA and AMD..."},
      {"role": "user", "content": "What are the risks to that outlook?"}
    ],
    "max_tokens": 150,
    "temperature": 0.7
  }' | jq '.choices[0].message.content'
```

**Check for:**
- Follow-up answer is relevant to the previous context
- Risks mentioned are specific to the previously named sector (not generic market risks)

## Performance Baseline

Record these numbers for comparison:

```bash
# Time a simple query

  -H "Content-Type: application/json" \
  -d '{"model": "tracealchemy", "messages": [{"role": "user", "content": "What is a P/E ratio?"}], "max_tokens": 100}' > /dev/null
```

| Metric | Expected (M4 32GB) | Notes |
|--------|-------------------|-------|
| Time to first token | < 2s | Model loads into GPU memory first time |
| Tokens per second | 15-30 t/s | Depends on quant and active parameters |
| Full 150-token response | ~5-10s | Acceptable for interactive use |

## What Could Go Wrong

| Problem | Likely Cause | Fix |
|---------|-------------|------|
| `curl: (7) Connection refused` | Server not running | Start it (Task 1.1.3) |
| Empty response or timeout | Context size too large / OOM | Restart with lower `--ctx-size` |
| Gibberish output | Model loaded incorrectly or wrong GGUF | Check model file integrity, re-download |
| `finish_reason: "length"` | Response was cut off at max_tokens | Increase `max_tokens` in the request |
| Very slow responses (>60s) | Low GPU offloading or swap pressure | Check `--n-gpu-layers`, monitor Activity Monitor |
| API returns HTML error page | Wrong endpoint URL | Ensure URL is `http://127.0.0.1:8080/v1/chat/completions` |

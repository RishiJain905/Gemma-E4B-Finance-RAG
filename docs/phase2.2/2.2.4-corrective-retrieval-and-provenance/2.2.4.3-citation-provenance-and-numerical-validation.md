# 2.2.4.3 — Citation Provenance & Numerical Validation

## Objective

Assign stable evidence IDs to every model-visible fact, document, tool result,
and calculation; require answers to cite those IDs; and deterministically flag
unsupported citations and financial numbers before returning a grounded answer.

## Why This Matters

`[Source: type/ticker]` proves only that a label was emitted. It cannot identify
the exact row/chunk/tool result, detect citations to evidence outside the
prompt, or verify that a stated number matches the supplied period and unit.
Finance answers need traceable support without paying for another free-form
self-critique generation.

## Step 1: Create stable model-visible evidence IDs

Extend `src/middleware/evidence.py` with `EvidenceItem` and
`assign_evidence_ids(items)`.

IDs are request-local, deterministic in final packed order, and formatted
`E1`, `E2`, ... . Each item retains:

- kind and original store/tool id;
- ticker/entities, metric, value, unit, period, as-of;
- source type/URL and freshness watermark;
- document body, parent/section/chunk metadata;
- subquery ids and retrieval scores;
- calculation operands/formula when derived.

The prompt renders an evidence header and `[E#]` marker. Evidence IDs never
replace durable storage identifiers in databases or APIs.

## Step 2: Parse citations into structured support links

Update citation parsing to accept `[E1]` and retain legacy
`[Source: type/ticker]` during a compatibility window. Add `EvidenceCitation`
to the response:

```text
evidence_id
source_type
ticker
metric
period
source_url
support_status: supported | missing | malformed
```

Every cited ID must exist in the final model-visible evidence ledger. Duplicate
citations collapse to one structured record while remaining in answer text.
Unknown or malformed IDs are never converted into a real source citation.

## Step 3: Validate specific numerical claims

Create `src/middleware/answer_validator.py` using only the standard library and
`decimal.Decimal`.

The validator:

1. Extracts currencies, percentages, signed values, ratios, and common scaled
   suffixes (`K`, `M`, `B`, `T`) from answer sentences.
2. Associates nearby `[E#]` citations with the sentence.
3. Normalizes formatting without changing precision.
4. Checks whether the cited evidence contains the value with compatible unit,
   metric/entity, and period, or contains a recorded deterministic calculation
   producing it.
5. Returns supported, unsupported, and ambiguous claim records.

Do not attempt full natural-language entailment or silently “correct” prose.
Numbers in dates, evidence labels, and clearly marked general examples need
separate rules to avoid false positives.

## Step 4: Apply an explicit validation policy

Configuration:

- `answer_validation: off|report|enforce` (initial default `report`);
- `require_evidence_ids: bool = False` during compatibility rollout.

Behavior:

- `off`: current response behavior;
- `report`: return answer plus validation metadata and log unsupported claims;
- `enforce`: a missing evidence ID or unsupported specific financial number
  downgrades grounding to `partial`; append a short support warning listing the
  affected sentence/claim ids;
- if the answer is wholly unsupported, return the existing honest refusal
  message rather than an uncited answer;
- validator errors fail soft to `report_unavailable`, never crash `/query`.

Do not make another model call to repair the answer in Phase 2.2.4.3.

Expose:

```json
{
  "citation_support_rate": 1.0,
  "numeric_claims_supported": 4,
  "numeric_claims_unsupported": 0,
  "validation_status": "supported"
}
```

## Step 5: Extend evaluation and observability

Add deterministic metrics:

- citation existence/precision/support rate;
- numeric claim support rate;
- unsupported numerical claim rate;
- entity/period/unit mismatch counts;
- validation downgrade/refusal rate.

Judge-based faithfulness remains separate and receives the exact evidence
trace. Promotion gates:

- at least 0.95 citation support on labeled answerable cases;
- unsupported numeric claims reduced at least 30% relative;
- zero accepted citations to IDs absent from model-visible evidence;
- false-positive numeric validation below 0.02 on labeled non-claim numbers;
- validator p95 below 10 ms for the maximum configured answer/evidence size.

**Files to modify:**
- `eval/metrics.py`
- `eval/score.py`
- `eval/gate.py`

## Testing

Cover exact/rounded display formats, percentages, negative values, billions,
ratios, zero, dates, different periods, incompatible currencies, derived
calculations, multiple citations, unknown IDs, uncited specific numbers, and a
validator exception. All tests use fixed strings and evidence dictionaries.

## Verification Checklist

- [ ] Every model-visible evidence item has a stable request-local `[E#]` id
- [ ] Structured citations resolve only to the final supplied evidence ledger
- [ ] Legacy source citations remain compatible during rollout
- [ ] Numeric claims validate value, unit, entity, period, or recorded calculation
- [ ] Dates/labels/examples do not create common false positives
- [ ] Enforcement downgrades or refuses unsupported answers without another model call
- [ ] Validator failures fail soft and remain observable
- [ ] Citation/numeric quality and latency gates are measured
- [ ] All validator tests are deterministic and offline

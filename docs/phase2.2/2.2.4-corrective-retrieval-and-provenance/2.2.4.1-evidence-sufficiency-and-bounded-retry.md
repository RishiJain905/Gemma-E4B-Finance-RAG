# 2.2.4.1 — Evidence Sufficiency & Bounded Corrective Retry

## Objective

Replace count-based grounding with a deterministic, route-aware evidence
sufficiency assessment. Answer immediately when requested obligations are
covered, perform at most one internal corrective retrieval when evidence is
borderline, and return an honest partial/refusal when required evidence is
missing.

## Why This Matters

Three returned rows currently imply “grounded” even if document bodies are
blank, irrelevant, stale, for the wrong ticker, or cover only one clause of a
compound question. More retrieval is not automatically better. The system
needs a small evidence gate that explains what is covered and chooses one
bounded corrective action instead of repeatedly querying or asking the model to
judge its own retrieval.

## Step 1: Define evidence obligations and outcomes

Create `src/middleware/evidence_grader.py` with:

- `EvidenceObligation` — subquery id, entities, metrics, periods, modalities,
  operations, freshness requirement, and minimum source class;
- `CoverageResult` — covered/missing fields and supporting evidence ids;
- `SufficiencyResult` — `sufficient|borderline|missing`, overall score for
  telemetry only, reason codes, coverage rows, conflicts, and allowed action.

Build obligations directly from the validated `QueryPlan`. Do not infer new
requirements from generated prose.

Status rules are explicit:

- `sufficient`: every required obligation has usable compatible evidence;
- `borderline`: the plan is plausibly answerable internally and exactly one
  documented correction can address the missing coverage;
- `missing`: required evidence is absent, stale beyond policy, contradictory
  without resolution, or would require an unaudited external source.

## Step 2: Grade usable evidence, not raw result count

The grader checks:

- nonblank document body or non-`None` fact/tool/calculation value;
- exact/validated entity match;
- requested metric and compatible aliases;
- requested period/as-of compatibility;
- required modality coverage (`fact`, `document`, `news`, `filing`, `macro`,
  `estimate`, or calculation);
- source authority for the question type;
- freshness and stale-disclosure requirements;
- unit/currency compatibility;
- duplicate parent/chunk removal;
- contradictions across sources/periods;
- retrieval score thresholds only when the score is meaningful for that
  channel.

RRF rank and record count are supporting signals, never calibrated confidence
on their own. Broad fallback facts unrelated to an obligation provide no
coverage.

Return machine-readable reason codes such as `blank_body`, `wrong_entity`,
`missing_period`, `stale_required_source`, `missing_qualitative_evidence`, and
`conflicting_units`.

**Files to modify:**
- `src/middleware/evidence_grader.py`

## Step 3: Map borderline outcomes to one corrective action

Define a small action enum:

- `broaden_ticker_filter` — retry without a low-confidence inferred ticker;
- `apply_validated_alias` — retry with known company/metric aliases;
- `expand_parent_section` — fetch the hit's heading/adjacent siblings;
- `run_derived_subqueries` — use the bounded decomposition from 2.2.4.2;
- `alternate_internal_modality` — add the one missing store/source route;
- `none`.

The action must be selected from reason codes and plan metadata; no model call
is used to choose it. `ExecutionBudget` consumes the second and final retrieval
round before execution.

Never add open web search, arbitrary URLs, unguarded refresh, or recursive
correction. If the second result remains insufficient, stop and preserve the
best covered evidence.

**Files to modify:**

## Step 4: Convert sufficiency into answer policy

Update grounding selection:

- `sufficient` -> `grounded`;
- covered subset with explicit missing obligations -> `partial`;
- no usable requested evidence -> `general` only when the existing graded
  policy allows stable general knowledge and no specific figures are needed;
- otherwise -> `refused` with concise missing/stale reason.

The answer prompt receives the covered and missing obligation list so the model
does not pretend a compound question was fully answered. Degraded answers use
the same status and reasons.

Expose optional response metadata:

```json
{
  "status": "partial",
  "reason_codes": ["missing_qualitative_evidence"],
  "covered_subqueries": ["sq0"],
  "missing_subqueries": ["sq1"],
  "corrective_action": "alternate_internal_modality",
  "retry_performed": true
}
```

## Step 5: Add controls and evaluation

Configuration:

- `enable_evidence_sufficiency: bool = False`
- `enable_corrective_retry: bool = False`
- `max_corrective_retries: int = 1` (hard clamp 0–1)

Measure coverage precision/recall, unnecessary retry rate, abstention F1,
unsupported-number rate, latency, and retrieval-round count. Promotion gates:

- abstention F1 at least 0.85;
- unsupported numerical claims reduced at least 30% relative;
- unnecessary corrective retry on simple queries no greater than 0.15;
- zero requests above two total retrieval rounds;
- single-turn answer correctness regresses by no more than 0.02.

**Files to modify:**

## Testing

Add offline fixtures for blank bodies, unrelated broad facts, wrong ticker,
missing period, stale required sources, mixed facts/documents, unit conflicts,
fully covered compound plans, and permanently missing evidence.

Assert that:

- count alone never creates `sufficient`;
- zero-valued facts remain usable;
- one documented correction consumes the final retrieval round;
- no retry occurs for sufficient or clearly missing evidence;
- correction never reaches the network or write tools;
- second-round insufficiency stops with partial/refusal;
- legacy behavior remains when flags are off.

## Verification Checklist

- [ ] Sufficiency is derived from plan obligations and usable evidence
- [ ] Entity, metric, period, modality, authority, freshness, and conflicts are checked
- [ ] Raw count/RRF rank is never treated as calibrated confidence
- [ ] Borderline evidence maps to one documented internal action
- [ ] Total retrieval rounds remain capped at two
- [ ] No web search, arbitrary URL, recursive retry, or write tool is reachable
- [ ] Missing obligations are visible to prompt and response consumers
- [ ] Partial/refusal behavior uses the same evidence result
- [ ] Quality and unnecessary-retry gates are measurable offline/live as appropriate

# 2.2.1.1 — Retrieved Document Contract & Prompt Policy

## Objective

Fix the P0 evidence-loss bug where Chroma retrieval results expose document
bodies under `document` while `PromptAugmenter` reads `text`, then establish
one shared evidence contract and one authoritative prompt-policy builder.
Blank document rows must never count as grounding, and every rendered fact must
retain its own ticker, period, source, and unit.

## Why This Matters

The current pipeline can retrieve relevant documents, count them in
`documents_used`, classify the request as grounded, and still send blank
document bodies to the model. That creates false confidence and invalidates the
faithfulness baseline. Prompt policy is also duplicated between
`src/middleware/app.py`, `PromptAugmenter`, and the direct eval path, so live and
offline requests can silently enforce different rules.

## Step 1: Fix the document-body contract first

Create `src/middleware/evidence.py` with small, dependency-free helpers:

- `document_body(document) -> str` reads the canonical `document` field first,
  then accepts `text` and `content` only as backward-compatible aliases for
  injected tests and older callers.
- `usable_documents(retrieval) -> list[dict]` returns only rows whose normalized
  body is non-blank.
- `usable_facts(retrieval) -> list[dict]` keeps facts with a metric and a
  non-`None` value; numeric zero remains valid evidence.
- `evidence_counts(retrieval) -> tuple[int, int]` returns usable fact and
  document counts.

The retriever output contract remains `document`; do not rename every
retrieval result or add a second stored copy of the body. All downstream
consumers must use the shared helper instead of open-coding key fallbacks.

Update `PromptAugmenter._format_documents_section` to render
`document_body(doc)`. Filter unusable rows before prompt assembly so an empty
`## Retrieved Documents` section is never emitted.

**Files to create:**
- `src/middleware/evidence.py`

**Files to modify:**
- `src/middleware/prompt_augmenter.py`
- `tests/test_prompt_augmenter.py`

## Step 2: Base grounding and response counts on usable evidence

Replace `app._grounding_level`'s raw list-length calculation with
`evidence_counts`. The same usable counts must populate `facts_used` and
`documents_used` in both normal and streaming terminal responses.

Contract:

- 3 or more usable facts/documents → `grounded`.
- 1 or 2 usable facts/documents → `partial`.
- 0 usable facts/documents → `none`.
- A document with metadata but an empty/whitespace body contributes zero.
- A fact whose value is `0` contributes one; a fact whose value is `None` does
  not.

This change must not mutate the retriever result or hide invalid rows from
debugging; it changes only model-visible evidence and evidence-derived counts.

**Files to modify:**
- `src/middleware/app.py`
- `tests/test_answer_policy.py`
- `tests/test_chat_client.py`

## Step 3: Preserve per-fact provenance in the prompt

Update `PromptAugmenter._format_facts_section` so each row uses that fact's
`ticker`, `period`, `source_type`, and `unit`. The request-level ticker is only
a fallback when the fact lacks a ticker; it must never overwrite a fact from a
different ticker in comparison or macro retrieval.

Render a stable citation for every fact:

`[Source: {fact.source_type}/{fact.ticker}]`

Preserve the value exactly as supplied apart from the existing display
formatting. Add comparison fixtures containing facts from two tickers and
assert that neither provenance record is relabeled.

**Files to modify:**
- `src/middleware/prompt_augmenter.py`
- `tests/test_prompt_augmenter.py`

## Step 4: Centralize the answer policy

Create `src/middleware/prompt_policy.py` as the only owner of strict/graded
system prompts and tool-aware policy guidance. Expose one public function:

`build_system_prompt(*, answer_policy, allow_general_fallback, intent,
grounding_level, tools_enabled) -> str`.

`src/middleware/app.py` must import this builder for non-streaming, streaming,
and tool-loop calls. `eval/run_eval.py`'s direct path must call the same builder
instead of importing the legacy `SYSTEM_PROMPT` constant.

Remove the duplicated global grounding rules from
`PromptAugmenter._build_system_instruction`. The augmented user message should
contain retrieved evidence, intent-specific task guidance, the raw question,
and output format; authoritative answer-policy rules belong only in the system
message. Keep strict mode byte-for-byte compatible through a constant owned by
`prompt_policy.py`.

## Testing

Extend the existing offline suites:

- `test_document_field_body_is_rendered` — a retriever-shaped row containing
  only `document` appears verbatim in the prompt.
- `test_blank_document_does_not_count_as_grounding` — metadata plus blank body
  produces `none` and `documents_used == 0`.
- `test_legacy_text_alias_remains_supported` — an injected `text` row still
  renders during the compatibility window.
- `test_zero_value_fact_is_usable` — a zero-valued fact remains evidence.
- `test_multi_ticker_fact_provenance_preserved` — ticker, period, source, and
  unit remain attached to each fact.
- `test_all_model_paths_share_prompt_policy` — plain, streaming, tool, and
  direct-eval payloads use the same policy builder for equivalent inputs.
- `test_strict_policy_is_unchanged` — strict rollback prompt remains identical.

No test may require ChromaDB, the middleware process, network access, or the
local model; use retriever-shaped dictionaries and mocked HTTP clients.

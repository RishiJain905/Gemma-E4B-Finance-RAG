# 2.2.5.1 — SEC CompanyFacts Structured Ingestion

## Objective

Ingest official SEC CompanyFacts/XBRL data as an authoritative structured
source while preserving the native concept, unit, period, filing, accession,
and fetch provenance needed for deterministic **as-of** queries. Keep every
source observation auditable, then expose a small configured set of canonical
finance metrics without overwriting lower-priority historical records.

## Why This Matters

The current `fundamentals` table stores one value for
`(ticker, metric, period)`. That is convenient for latest-value lookup but
cannot represent SEC amendments, comparative facts repeated in later filings,
multiple XBRL concepts for the same business metric, or what was knowable on a
past date. CompanyFacts is the SEC's structured source for these observations.
Using it gives exact filing-backed numbers and provenance without asking the
local model to extract every fact from prose.

## Step 1: Add the CompanyFacts client and normalization contract

Create `src/sec/companyfacts.py` with `SECCompanyFactsIngestor`. It must call
the official endpoint
`https://data.sec.gov/api/xbrl/companyfacts/CIK##########.json` through one
persistent `requests.Session`, using the configured descriptive SEC
`User-Agent`, timeout, retry/backoff, and a request delay that remains below
the SEC rate limit.

Expose a public `resolve_cik(ticker)` method from
`src/sec/edgar_fetcher.py`; retain `_resolve_cik()` as a compatibility wrapper
so filing discovery and CompanyFacts share one ticker-to-CIK implementation.

`SECCompanyFactsIngestor.fetch_for_ticker(ticker)` returns a summary dict:

```python
{
    "ticker": "NVDA",
    "cik": "0001045810",
    "facts_seen": 1200,
    "facts_written": 1184,
    "facts_skipped": 16,
    "errors": [],
    "source_accessed_at": "2026-07-10T12:00:00Z",
}
```

Normalize every accepted unit observation to this internal contract:

```python
{
    "ticker": "NVDA",
    "cik": "0001045810",
    "taxonomy": "us-gaap",
    "concept": "RevenueFromContractWithCustomerExcludingAssessedTax",
    "label": "Revenue",
    "description": "...",
    "value_text": "60922000000",
    "value_numeric": 60922000000.0,
    "unit": "USD",
    "period_start": "2024-01-29",       # empty string for instant facts
    "period_end": "2025-01-26",
    "period_kind": "annual",            # instant|quarterly|ytd|annual
    "fiscal_year": 2025,
    "fiscal_period": "FY",
    "form": "10-K",
    "filed_at": "2025-02-26",
    "accession": "0001045810-25-000023",
    "frame": "CY2024",                  # empty string when absent
    "source_url": "https://data.sec.gov/api/xbrl/companyfacts/CIK0001045810.json",
    "source_accessed_at": "2026-07-10T12:00:00Z",
}
```

Parse JSON numbers with `decimal.Decimal` and store their canonical decimal
string in `value_text`; `value_numeric` exists for current numeric query APIs.
Skip non-finite, non-numeric, missing-accession, or missing-period-end entries
with counted reasons rather than failing the ticker. Derive `period_kind`
deterministically from start/end duration, `fp`, and form; do not ask an LLM.

Create `configs/sec_companyfacts.yaml` with:

- `enabled: false` for the initial rollout;
- allowed taxonomies and forms (`10-K`, `10-K/A`, `10-Q`, `10-Q/A` initially);
- timeout, retry, and request-delay settings;
- a small canonical metric map whose ordered concept list is explicit, for
  example `total_revenue`, `net_income`, `diluted_eps`, `total_assets`,
  `total_liabilities`, `stockholders_equity`, `operating_cash_flow`, and
  `shares_outstanding`;
- expected units and period kinds for each canonical metric.

The raw table stores all accepted configured facts. The metric map controls
query projection only; changing an alias must not delete source rows.

**Files to create:** `src/sec/companyfacts.py`,
`configs/sec_companyfacts.yaml`.

**Files to modify:** `src/sec/edgar_fetcher.py`, `src/sec/__init__.py`.

## Step 2: Add a provenance-preserving SQLite table

Add `sec_companyfacts` to both `docs/phase1.2/schema.sql` and
`SQLiteStore._inline_schema()` in `src/storage/sqlite_store.py`:

```sql
CREATE TABLE IF NOT EXISTS sec_companyfacts (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ticker TEXT NOT NULL,
    cik TEXT NOT NULL,
    taxonomy TEXT NOT NULL,
    concept TEXT NOT NULL,
    label TEXT,
    description TEXT,
    value_text TEXT NOT NULL,
    value_numeric REAL NOT NULL,
    unit TEXT NOT NULL,
    period_start TEXT NOT NULL DEFAULT '',
    period_end TEXT NOT NULL,
    period_kind TEXT NOT NULL,
    fiscal_year INTEGER,
    fiscal_period TEXT,
    form TEXT NOT NULL,
    filed_at TEXT NOT NULL,
    accession TEXT NOT NULL,
    frame TEXT NOT NULL DEFAULT '',
    source_url TEXT NOT NULL,
    source_accessed_at TEXT NOT NULL,
    ingested_at TEXT NOT NULL DEFAULT (datetime('now')),
    UNIQUE (
        ticker, taxonomy, concept, unit, period_start,
        period_end, accession, frame
    )
);
```

Add indexes for `(ticker, concept, period_end)`, `(ticker, filed_at)`,
`accession`, and `(ticker, period_kind, period_end)`. Empty strings, rather
than nullable `period_start`/`frame`, are required so SQLite's nullable-unique
semantics cannot create duplicate instant facts on repeated ingestion.

Implement in `src/storage/sqlite_store.py`:

- `upsert_sec_companyfacts(rows) -> dict` in one transaction, with an
  `ON CONFLICT ... DO UPDATE` that refreshes the value and fetch provenance;
- `query_sec_companyfacts(ticker, concepts, *, units=None,
  period_kinds=None, period_end=None, as_of=None) -> list[dict]`;
- `count_sec_companyfacts(ticker=None) -> int` for status and migration checks.

`as_of` applies to `filed_at`, not `period_end`: a row is eligible only when
`filed_at <= as_of`. Default `as_of` is the current UTC date. Invalid dates
raise a local validation error before SQL; they never silently become a latest
query.

Do not copy these raw rows into `fundamentals`. That table's uniqueness would
discard the exact provenance this feature is adding.

**Files to modify:** `docs/phase1.2/schema.sql`,
`src/storage/sqlite_store.py`.

## Step 3: Define canonical selection and conflict behavior

Add `Store.get_companyfacts(ticker, metrics, *, periods=None, as_of=None)` in
`src/storage/store.py`. It loads the ordered concept/unit rules from
`configs/sec_companyfacts.yaml`, queries eligible raw rows, and returns facts
in the existing retrieval shape plus the SEC fields:

```python
{
    "ticker": "NVDA",
    "metric": "total_revenue",
    "value": 60922000000.0,
    "value_text": "60922000000",
    "unit": "USD",
    "period": "2025-01-26",
    "period_start": "2024-01-29",
    "period_type": "annual",
    "source_type": "sec_companyfacts",
    "source_url": "...",
    "source_accessed_at": "...",
    "taxonomy": "us-gaap",
    "concept": "RevenueFromContractWithCustomerExcludingAssessedTax",
    "accession": "0001045810-25-000023",
    "form": "10-K",
    "filed_at": "2025-02-26",
    "as_of": "2026-07-10",
    "conflict": False,
    "alternatives": [],
}
```

Use one deterministic policy:

1. Filter by ticker, requested canonical metric, expected unit/period kind,
   requested period, and `filed_at <= as_of`.
2. Preserve every candidate in SQLite.
3. For the same concept/unit/period, prefer the most recently filed eligible
   observation. This naturally lets a later amendment supersede the original
   for a current query while an earlier `as_of` still returns the original.
4. Across concept aliases, apply the configured concept order only after the
   period/unit filters.
5. If eligible candidates for the same canonical metric, unit, and period have
   distinct values, return the selected row with `conflict=True` and compact
   provenance-only `alternatives`; never average or silently overwrite them.
6. When merged with legacy `fundamentals` later in 2.2.5.3, CompanyFacts wins
   only for reported GAAP metrics with the same ticker, unit, and period.
   Estimates, market prices, macro series, and management guidance retain
   their own source policy.

Selection must be a pure helper with stable ordering so it can be exhaustively
tested without SQLite or the network.

**Files to modify:** `src/storage/store.py`.

## Step 4: Register freshness and scheduler execution

Register `sec_companyfacts` as its own source in
`UnifiedScheduler.SOURCES`, after SEC filing discovery and before downstream
qualitative sources. Its runner constructs `SECCompanyFactsIngestor`, ingests
each core ticker independently, records per-ticker failures, and continues.

Add:

- `sec_companyfacts` to `UnifiedScheduler.DAILY_SOURCES`;
- `sec_companyfacts` TTL in `configs/watchlist.yaml` (24 hours initially);
- a `Store.FRESHNESS_SOURCES` entry using cache source
  `sec_companyfacts` and TTL key `sec_companyfacts`;
- per-ticker `mark_source_fresh` only after a valid response is committed;
- `mark_source_stale` with the local error when CIK lookup, HTTP, JSON, or
  transaction work fails.

The unified scheduler's existing source-level isolation remains intact. A
CompanyFacts error must not stop filing text, FRED, Yahoo, or any other source.

**Files to modify:** `src/scheduler/__init__.py`, `src/storage/store.py`,
`configs/watchlist.yaml`.

## Step 5: Keep rollout additive and observable

When `enabled: false`, no endpoint, scheduler cadence, retrieval result, or
existing fact query changes. When enabled, scheduler/status output reports
facts seen/written/skipped and freshness, without logging full payloads.

Do not add a model call, embedding call, GraphRAG node, or generated summary to
this ingestion path. Middleware retrieval integration and source-priority
evaluation are owned by 2.2.5.3 after the authoritative data is present.

## Testing

Create `tests/fixtures/sec/companyfacts_sample.json` and
`tests/test_sec_companyfacts.py`:

- `test_request_uses_padded_cik_and_required_user_agent` — mock the HTTP
  session and assert the official URL/headers; no network.
- `test_normalizes_duration_instant_and_ytd_facts` — fixture rows receive
  stable `period_kind` values.
- `test_decimal_text_and_unit_are_preserved` — `value_text`, numeric value,
  and native unit survive a round trip.
- `test_reingestion_is_idempotent` — ingesting the fixture twice produces the
  same row count and updates fetch provenance.
- `test_as_of_excludes_later_filing` — a filing after the cutoff is never
  selected even when its period is earlier.
- `test_amendment_precedence_preserves_original` — current selection prefers
  the eligible amendment while historical as-of lookup returns the original;
  both rows remain stored.
- `test_conflicting_concepts_are_reported_not_averaged`.
- `test_metric_alias_priority_is_deterministic`.
- `test_bad_fact_is_counted_and_siblings_continue`.
- `test_scheduler_isolates_ticker_failure` and
  `test_disabled_source_does_not_fetch`.

All tests use temporary SQLite, fixture JSON, a fake clock, and a mocked HTTP
session. They must not contact SEC, Chroma, middleware, embeddings, or the
model.

Acceptance gates:

- 100% of accepted fixture rows retain taxonomy, concept, unit, period,
  accession, filing date, source URL, and fetch timestamp.
- A second identical ingestion creates zero duplicate rows.
- Historical as-of tests have zero look-ahead selections.
- Conflicting values have zero silent overwrites or averages.
- Disabled mode performs zero HTTP calls and leaves existing fact behavior
  unchanged.

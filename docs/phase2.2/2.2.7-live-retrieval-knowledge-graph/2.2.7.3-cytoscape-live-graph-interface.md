# 2.2.7.3 — Cytoscape Live Graph Interface

## Objective

Build a distinctive, localhost-only interactive interface that visualizes live
query traces and supports expand-on-demand corpus exploration. Use Cytoscape.js
as the graph renderer, a small static HTML/CSS/JavaScript application, and no
frontend framework or Node build chain.

## Why This Matters

Three.js is a low-level 3D renderer: graph layout, hit testing, labels,
selection, filtering, and accessibility would be custom application work.
Sigma.js is a strong WebGL choice when tens of thousands of nodes must be
visible at once. This design deliberately keeps the visible graph bounded and
needs compound groups, rich events, multiple layouts, and detailed selection.
Cytoscape.js provides those graph-native primitives with less code and clearer
2D inspection.

References:

- [Cytoscape.js documentation](https://js.cytoscape.org/)
- [Sigma.js WebGL graph renderer](https://v4.sigmajs.org/)
- [Three.js raycasting API](https://threejs.org/docs/pages/Raycaster.html)

## Step 1: Serve a self-contained local application

Create:

```text
src/middleware/static/graph/
  index.html
  graph.css
  graph.js
  fonts/RecursiveSans.woff2
  fonts/CommitMono.woff2
  vendor/cytoscape.min.js
  vendor/LICENSE-cytoscape.txt
  vendor/LICENSE-fonts.txt
  vendor/SHA256SUMS
```

Pin one audited Cytoscape.js release locally. Do not load scripts, fonts, or
analytics from a CDN; the interface must work without internet access and must
not leak corpus/query metadata to third parties.

Mount static assets only when `enable_graph_observer=true`:

- `GET /graph` returns `index.html`;
- `GET /graph/static/*` serves pinned assets with safe MIME types and no
  directory listing;
- use same-origin API/SSE URLs, so no broad CORS policy is required.

## Step 2: Use a focused “financial telemetry” visual system

Aesthetic direction: **industrial financial observability**, not a generic AI
dashboard.

- near-black graphite canvas with subtle grid/noise texture;
- warm ivory text, cyan for retrieval flow, amber for pending/borderline,
  green for supported evidence, coral for errors/conflicts, muted steel for
  dropped/inactive context;
- locally bundled open fonts: a compact humanist sans for UI and a legible mono
  face for metrics/ids, both with license files;
- thin directional edges, restrained glow only on active stages, and no purple
  gradient/glass-card motif;
- motion communicates state transitions, not decoration; honor
  `prefers-reduced-motion`.

Node language:

- query: rounded rectangle;
- subquery/stage: compact labeled process nodes;
- tool: hexagon;
- fact/calculation: diamond;
- document/section: page shape;
- source: ring;
- answer: double-border terminal node;
- supported/partial/error states use color plus icon/line style, never color
  alone.

## Step 3: Build two clear modes

### Live Trace

- automatically select the newest active query unless the user pinned another;
- `breadthfirst` left-to-right layout grouped by compile, route, retrieve,
  evidence, generate, validate;
- animate only newly active nodes/edges;
- timeline scrubber filters graph state by event sequence;
- select a node to inspect safe metadata, excerpt, scores, freshness, timings,
  source URL, and support relationships;
- filters for subquery, source, ticker, evidence kind, status, and cited-only;
- “follow live” toggle, fit/reset, pin node, collapse stage, and export current
  redacted snapshot JSON.

### Corpus Explorer

- begin with source groups/counts rather than all facts/documents;
- search ticker, metric, accession, source, or document family;
- double-click/Enter expands one paginated neighbor page;
- `cose` layout for bounded local neighborhoods;
- show current corpus revision and a visible reload notice when it changes;
- never auto-expand beyond configured visible element limits.

The two modes share the inspector and visual legend but never mix trace-local
answer nodes into the corpus projection.

## Step 4: Implement resilient SSE state updates

`graph.js`:

- loads a snapshot first, then opens `EventSource('/graph/api/events')`;
- applies deltas by stable id and sequence;
- ignores duplicates/out-of-order old events;
- on `reset_required`, reloads the selected snapshot;
- reconnects with bounded exponential delay and visible connection state;
- batches rapid deltas into one animation frame;
- stops layouts while the user is dragging/pinning and resumes intentionally;
- caps visible elements and drops no server data silently—show hidden counts.

If Cytoscape or SSE initialization fails, show a useful error panel and a
read-only trace table rather than a blank canvas.

## Step 5: Make inspection accessible

- all controls and node selection are keyboard reachable;
- provide focus-visible styles and `aria-live` connection/query status;
- include a synchronized table/list view of currently visible nodes/edges;
- minimum target size and contrast meet WCAG 2.1 AA;
- labels can be enlarged without clipping the inspector;
- reduced-motion mode removes pulsing/animated edge flow;
- tooltips are supplementary—details are available through selection/focus;
- responsive layout supports a side monitor and a single laptop screen.

## Testing

Without adding a runtime frontend framework:

- Python tests verify `/graph`, local asset paths, CSP/security headers, pinned
  vendor hash/license, required landmarks/controls, and no external URLs;
- pure JS state functions (`applyDelta`, filters, element caps) are isolated for
  browser-console/static test fixtures;
- an implementation-time browser smoke test verifies selection, keyboard
  traversal, live delta rendering, reconnect/reset, corpus expansion, reduced
  motion, and no console errors.

The browser smoke test is run only when UI implementation is being verified; it
does not start or load the local model.

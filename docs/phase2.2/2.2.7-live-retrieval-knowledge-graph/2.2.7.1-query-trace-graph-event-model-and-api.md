# 2.2.7.1 — Query Trace Graph Event Model & API

## Objective

Capture each query's real planning, retrieval, tool, evidence, citation, and
validation path as a bounded graph trace, then expose snapshots and live updates
over localhost. The observer must be request-scoped, non-blocking, redacted, and
incapable of changing query behavior.

## Why This Matters

Timings and result counts explain how long a request took, but not which
subquery retrieved which fact/document, why a corrective retry ran, which
source supported the answer, or where evidence was discarded. A side graph can
make the RAG pipeline inspectable while `chat.py` is running. It must reflect
actual executed events rather than ask the model to invent a post-hoc diagram.

## Step 1: Define graph trace primitives

Create `src/middleware/graph_observer.py` with serializable records:

### `GraphNode`

- `id` — query-scoped stable id;
- `query_id`;
- `kind` — `query|plan|subquery|stage|tool|evidence|source|answer|citation`;
- `label` and short safe summary;
- `status` — `pending|active|complete|dropped|fallback|partial|error`;
- optional `group_id` for compound query/stage containers;
- safe metadata such as ticker, metric, period, source type, rank, score,
  freshness, counts, elapsed time, and evidence id;
- creation/update sequence.

### `GraphEdge`

- stable id, source, target, and query id;
- relation — `compiled_to|contains|routed_to|retrieved|returned|from_source|
  expanded_from|supports|cited_by|corrected_by|validated_as`;
- optional rank/score/status metadata.

### `GraphDelta`

- `schema_version`, `query_id`, monotonic `sequence`, timestamp;
- operation — `upsert_node|upsert_edge|remove|trace_complete|trace_evicted|
  reset_required`;
- one node/edge or safe trace summary.

Ids reference the existing query plan, evidence ledger, and stream event ids.
Do not create a parallel notion of evidence or sources.

**Files to create:**
- `src/middleware/graph_observer.py`
- `tests/test_graph_observer.py`

## Step 2: Add a bounded non-blocking `TraceHub`

`TraceHub` owns:

- an in-memory ring buffer of completed/recent active traces;
- subscriber queues for the graph SSE endpoint;
- limits by trace count, total node/edge count, excerpt bytes, and TTL;
- deterministic eviction and `trace_evicted` notifications;
- snapshot reconstruction from stored deltas.

Recommended defaults:

- 100 traces;
- 5,000 total nodes plus edges;
- one hour TTL;
- 1,000-character maximum stored evidence excerpt;
- 256 queued events per subscriber.

`publish(delta)` must never await a slow browser or block retrieval. When a
subscriber queue is full, mark that subscriber for `reset_required`; the
browser reloads a current snapshot. Observer exceptions are logged once and
discarded. Query execution always continues.

No trace persists to disk by default.

**Files to modify:**
- `src/middleware/graph_observer.py`
- `src/middleware/config.py`
- `configs/middleware.yaml`
- `tests/test_graph_observer.py`

Configuration:

- `enable_graph_observer: bool = False`
- `graph_trace_limit: int = 100`
- `graph_element_limit: int = 5000`
- `graph_trace_ttl_s: int = 3600`
- `graph_excerpt_chars: int = 1000`

## Step 3: Instrument the executed query path

Publish deltas from the shared query path at these points:

1. query accepted;
2. conversation compilation and query plan validated;
3. lane selected;
4. each retrieval/tool/stage starts and completes;
5. evidence normalized, graded, selected, dropped, or expanded;
6. corrective action selected/completed;
7. generation starts/completes;
8. citations/numerical claims validate;
9. terminal response produced.

Subscribe `TraceHub` to the one request-scoped `QueryEvent` emitter introduced
by 2.2.6.1. Extend that internal event with allowlisted evidence references
where needed, then serialize it separately for chat SSE and graph deltas. Do
not add a second set of stage callbacks. Instrumentation consumes actual
objects/results and must not re-run retrieval or parse the final answer to
reconstruct earlier stages.

With adaptive mode disabled, emit a smaller legacy trace containing query,
intent, retrieval, evidence, sources, answer, and citations.

## Step 4: Expose read-only localhost trace endpoints

Create `src/middleware/graph_api.py` as an `APIRouter`:

- `GET /graph/api/traces?limit=25` — recent trace summaries;
- `GET /graph/api/traces/{query_id}` — complete current snapshot;
- `GET /graph/api/traces/{query_id}/evidence/{evidence_id}` — bounded safe
  evidence details already present in that trace;
- `GET /graph/api/events` — SSE deltas for all new local queries;
- `GET /graph/api/health` — observer enabled, counts, limits, oldest/newest
  sequence, and dropped/reset counts.

Support `Last-Event-ID` or an explicit last sequence. If the requested sequence
was evicted, send `reset_required` followed by no stale deltas.

Return 404 when the observer is disabled. Endpoints are read-only and cannot
refresh, delete, replay, or modify data/query state.

**Files to create:**
- `src/middleware/graph_api.py`
- `tests/test_graph_api.py`

**Files to modify:**

## Step 5: Redact by construction

Never place these fields in graph deltas/snapshots:

- system/user prompts in full;
- full conversation history;
- secrets, headers, API keys, model paths, or `.env` values;
- tool schemas or unbounded raw tool arguments/results;
- entire filing/transcript/document bodies;
- generated model reasoning or hidden tokens.

Question text is configurable: default to a 200-character preview plus SHA-256
digest. Evidence uses the configured excerpt and metadata. Full local evidence
details require the specific trace/evidence endpoint and remain capped.

Add a recursive key denylist for `key|token|secret|authorization|cookie|path`
and explicit allowlists per node kind. Redaction tests use canary secrets.

## Testing

Offline tests verify stable ids/sequences, event ordering, legacy/adaptive
traces, exact source/evidence edges, no retrieval replay, ring/TTL eviction,
slow subscriber reset, snapshot recovery, observer-disabled behavior, and
recursive canary redaction.

Performance gate: publishing a normal delta has p95 below 2 ms in an offline
benchmark and a blocked subscriber adds no query-path await.

## Verification Checklist

- [x] Graph nodes/edges come from executed query/evidence objects
- [x] No retrieval/model call is repeated to construct the trace
- [x] TraceHub is bounded by count, elements, excerpt size, queue, and TTL
- [x] Slow/disconnected browsers cannot block or fail a query
- [x] Snapshots and SSE deltas are versioned and recover after eviction
- [x] Endpoints are read-only and disabled by default
- [x] Prompts, secrets, full documents, and model reasoning are excluded
- [x] Legacy and adaptive paths both produce useful traces
- [x] Event publishing meets the non-blocking latency gate

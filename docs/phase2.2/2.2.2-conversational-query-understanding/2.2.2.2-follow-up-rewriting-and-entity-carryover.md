# 2.2.2.2 — Follow-Up Rewriting & Entity Carryover

## Objective

Compile the current turn and bounded history into a standalone retrieval query
while preserving the user's raw question unchanged. Resolve obvious ticker,
metric, period, and operation carryover deterministically; use at most one
optional structured planner call only when the request remains genuinely
ambiguous.

## Why This Matters

Passing raw history directly to generation is not enough. Retrieval still sees
the current fragment, so “same period,” “what about AMD,” and “why did that
change?” embed and search poorly unless prior context is made explicit. A
separate retrieval query improves search without rewriting the user's request
or forcing every normal turn through another slow model call.

## Step 1: Create a deterministic conversation state

Extend `src/middleware/conversation.py` with `ConversationState`:

- ordered active tickers/entities;
- active metrics;
- explicit timeframe/period;
- last supported operations/intents;
- last user question and grounded answer metadata;
- `topic_id` and `resolution_sources` for observability.

Build state from structured prior-turn metadata first. Text inspection may
recover only values the existing `IntentParser`/symbol resolver can validate.
Assistant prose must never be treated as authoritative evidence for a new
numeric value.

Rules:

- explicit current-turn values always win;
- “what about X?” replaces the primary entity and carries compatible metric,
  period, and operation;
- “same period/metric” carries only the named slot;
- pronouns may carry an entity only when exactly one active entity exists;
- an explicit new topic clears incompatible carried slots;
- `/ticker` remains an explicit override and outranks history;
- stale or ungrounded prior answers do not contribute facts.

**Files to modify:**
- `src/middleware/conversation.py`
- `tests/test_conversation.py`

## Step 2: Produce a separate standalone retrieval query

Create `CompiledQuestion` in `src/middleware/conversation.py`:

```text
raw_question
retrieval_query
carried_entities
carried_metrics
carried_timeframe
topic_reset
ambiguous_slots
resolution_sources
```

`compile_question(raw_question, selected_history, override_ticker)` must:

1. Parse the raw turn with the current resolver and intent rules.
2. Carry only missing compatible slots from `ConversationState`.
3. Render a compact standalone retrieval query from validated slots and the
   untouched current turn.
4. Keep `raw_question` byte-for-byte unchanged for prompt display and answer
   generation.

Example:

```text
history: "Show NVDA revenue for FY2025."
turn:    "What about AMD?"
query:   "AMD total revenue FY2025"
```

The compiled query is retrieval input only. It must not be shown as though it
were the user's wording.

**Files to modify:**

- `src/middleware/prompt_augmenter.py`
- `src/middleware/models.py`

Expose optional response metadata: `retrieval_query`, carried slot names, and
`topic_reset`. Omit full history from responses.

## Step 3: Add an optional bounded ambiguity fallback

Create `src/middleware/query_rewriter.py` with one function that accepts only
the selected history, raw question, and deterministic unresolved slots. It may
call the configured model once and must request strict JSON:

```json
{
  "standalone_query": "...",
  "entities": ["NVDA"],
  "metrics": ["gross_margin"],
  "timeframe": "FY2025",
  "topic_reset": false
}
```

Guardrails:

- disabled by default;
- consume the shared Phase 2.2 planning-call budget;
- validate entities through `SymbolResolver` and metrics through the known
  metric catalog;
- reject any entity, metric, period, or number not present in the current turn,
  selected history, or validated catalog;
- do not expose retrieved documents to the rewriter;
- on timeout, invalid JSON, drift, or model unavailability, retain the
  deterministic compiled query and mark ambiguity in metadata.

Configuration:

- `enable_conversation_rewrite: bool = False` for initial evaluation, promoted
  to the shipped default only after the conversational gates pass
- `enable_llm_rewrite_fallback: bool = False`
- `conversation_rewrite_timeout_s: float = 15`

## Step 4: Evaluate carryover and topic shifts

Use `eval/golden/finance_conversations.jsonl` from 2.2.1.3. Capture both the
raw and compiled query plus carried slots in the evidence trace.

Shipping gates:

- entity, metric, and timeframe carryover accuracy each at least 0.90;
- validated entity preservation at least 0.95;
- invented-entity rate no greater than 0.01;
- topic-reset accuracy at least 0.90;
- multi-turn Recall@10 improves at least 10 percentage points;
- single-turn retrieval nDCG@10 regresses by no more than 0.02;
- deterministic turns make zero rewrite-model calls.

**Files to modify:**

- `tests/test_eval_harness.py`

## Testing

Add offline cases for:

- entity substitution with “what about AMD?”;
- carrying only timeframe with “same period”;
- carrying only metric with “same metric”;
- pronoun resolution with one active entity;
- refusing pronoun carryover with multiple active entities;
- explicit topic shift clearing incompatible slots;
- `/ticker` override winning over history;
- raw question remaining unchanged;
- rewritten query containing only validated values;
- invalid/timeout planner output falling back without raising;
- deterministic cases making no model request.

All planner HTTP calls are mocked. No local model or network access is allowed.

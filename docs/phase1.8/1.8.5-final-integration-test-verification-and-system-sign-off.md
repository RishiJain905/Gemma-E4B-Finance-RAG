# 1.8.5 — Final Integration Test, Verification & System Sign-Off

## Objective

Run the complete verification suite for the entire RAG system — every test, every endpoint, every data source, every failure mode. This is the **final sign-off** that confirms the system is complete, reliable, and ready for production use.

## Why This Matters

Phase 1.8 is the last phase. After this, the system needs to run unattended — ingesting data, answering queries, and recovering from failures without manual intervention. The final verification ensures:

- **Every feature works** — no regressions from any prior phase
- **The system is reliable** — it handles failures gracefully
- **The system is observable** — health checks, logs, and metrics tell you what's happening
- **The system is documented** — anyone can set it up and use it
- **The system is complete** — no loose ends, no TODO comments, no dead code

## Step 4: Verify Failure Modes

Test that the system handles failures gracefully:

```bash
# 1. Model unavailable
# Stop llama-server, then query
echo "=== Degraded Mode (no model) ==="
curl -s -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{"question": "What is NVDA revenue?", "refresh": false}' | python -m json.tool
# Expected: model_available=false, answer shows raw data

# 2. Invalid ticker
echo "=== Invalid Ticker ==="
curl -s http://localhost:8000/freshness/INVALID | python -m json.tool
# Expected: returns empty sources, overall="never_fetched"

# 3. Empty query
echo "=== Empty Query ==="
curl -s -X POST http://localhost:8000/query \
  -H "Content-Type: application/json" \
  -d '{"question": ""}' | python -m json.tool
# Expected: 422 validation error

# 4. Refresh with unknown source
echo "=== Unknown Source ==="
curl -s -X POST http://localhost:8000/refresh/NVDA \
  -H "Content-Type: application/json" \
  -d '{"sources": ["unknown_source"]}' | python -m json.tool
# Expected: refreshes nothing, returns empty refreshed list

# 5. Scheduler with broken source
echo "=== Scheduler Partial Failure ==="
# Temporarily break a source config, run scheduler
# Expected: other sources still run, broken source shows error
```

**Acceptance criteria:**
- [ ] Query returns degraded answer when model is unavailable
- [ ] Invalid ticker returns empty but valid response
- [ ] Empty query returns 422 validation error
- [ ] Unknown source in refresh is silently skipped
- [ ] Scheduler continues when one source fails
- [ ] Circuit breaker opens after repeated failures
- [ ] Dead-letter queue stores persistently failing items

```markdown
# Architecture

## Overview

Gemma-E4B-Finance-RAG is a hybrid retrieval-augmented generation system for financial research. It combines structured data (SQLite) with semantic search (ChromaDB) and a fine-tuned LLM (TraceAlchemy) to answer financial questions with grounded, citable answers.

## System Components

### 1. Data Sources (6 total)

| Source | Type | API | Cadence | Auth Required |
|--------|------|-----|---------|--------------|
| SEC EDGAR | Regulatory filings | RSS + direct HTTP | Real-time | No |
| Yahoo Finance | Market data | yfinance (Python) | Daily | No |
| FRED | Economic indicators | fredapi | Daily | API key |
| GDELT | Global news | gdelt (Python) | Every 15min | No |
| Earnings Transcripts | Call transcripts | Web scraping | Quarterly | No |
| Company IR Pages | Press releases | RSS feeds | On-demand | No |

### 2. Ingestion Pipeline

[Flow diagram showing: Source → Collector → Parser (TraceAlchemy) → SQLite + ChromaDB]

The scheduler orchestrates all ingestion via `UnifiedScheduler`:
- **Daily** (market open): Yahoo Finance, FRED, SEC discovery, IR pages
- **Hourly**: GDELT news
- **Weekly** (weekend): Earnings transcripts, full SEC pipeline
- **On-demand**: Triggered by staleness-aware queries

### 3. Storage Layer

**SQLite** (`data/finance.db`):
- `facts` — structured financial metrics (ticker, metric, value, period)
- `cache_meta` — freshness tracking (ticker, source, last_updated, ttl)
- `filing_index` — SEC filing registry
- `dead_letter` — failed ingestion items

**ChromaDB** (`data/chroma/`):
- Document embeddings with metadata (ticker, source, date)
- Semantic search across all ingested documents

### 4. Middleware (FastAPI)

Endpoints:
- `GET /health` — System health check
- `POST /query` — Full RAG query pipeline
- `POST /search` — Raw hybrid search (bypasses model)
- `GET /freshness/{ticker}` — Data freshness report
- `POST /refresh/{ticker}` — On-demand data refresh
- `GET /macro/snapshot` — Macro-economic snapshot
- `GET /sentiment/{ticker}` — News sentiment summary

### 5. Model (TraceAlchemy)

Fine-tuned Gemma 4 E4B (2.6B activated / ~9B total, MoE) served via llama.cpp's `llama-server`:
- Port: 8087
- Context: 32K tokens
- GPU layers: 99 (full offload)
- Embedding endpoint: `/v1/embeddings`

## Data Flow

### Ingestion Flow
```
External API → Collector → Raw Data → TraceAlchemy Parser → Structured Facts (SQLite)
                                                          → Document Embeddings (ChromaDB)
                                                          → Cache Meta Update
```

### Query Flow
```
User Question → Intent Parser → Hybrid Retriever → Prompt Augmenter → TraceAlchemy → Answer
                    │                │                    │
              ticker/metrics    SQLite + ChromaDB    Context Assembly
```

## Failure Modes & Recovery

| Failure | Detection | Recovery |
|---------|-----------|----------|
| API unreachable | HTTP timeout | Retry with backoff (3 attempts) |
| Rate limited | HTTP 429 | Backoff + jitter |
| Persistent failure | Circuit breaker (5 failures) | Auto-recovery after 5 min |
| Model unavailable | Health check | Degraded mode (raw data) |
| Stale data | Cache TTL check | On-demand refresh |
```

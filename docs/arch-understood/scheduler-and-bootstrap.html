How ingestion works: UnifiedScheduler & bootstrap

Six data sources — SEC EDGAR, Yahoo Finance, FRED, GDELT, earnings transcripts, and IR pages — are ingested into data/finance.db (SQLite) and data/chroma (ChromaDB) by one orchestrator: UnifiedScheduler. It runs in four modes, gates every source by freshness, and isolates one source's failure from the rest.

The four modes + --force

Each mode selects a different set of sources from configs/sources.yaml by matching its cadence/run_modes.

hourly
fast-moving sources only
  • 1 of 23 sources: gdelt
  • only source whose 6h TTL needs sub-daily refresh
daily
TTL-expired refresh
  • 20 of 23 sources
  • universe, SEC discovery + companyfacts, market data, macro, IR pages, estimates
  • SEC filings: discovery only (queued, not parsed)
weekly
the deep-processing pass
  • 3 of 23 sources: sec_filings (full pipeline), cftc, earnings_transcripts
  • only mode that parses queued SEC filing text into facts + embeddings
all --force
manual, ad hoc
  • all 23 sources, TTL freshness ignored
  • request budgets still apply
  • still discovery-only for sec_filings — see note below
Audit finding · 2026-07-17
147 SEC filings sat unprocessed because deep_sec — which enables the full parse-and-embed pipeline — is only set when mode == "weekly" (src/scheduler/__init__.py). daily, hourly, all, and even the dedicated bootstrap mode only discover filings into the queue; none of them process the queue. Run weekly --force to drain a backlog.
--force skips the per-source TTL freshness check (_is_stale) — it does not skip request budgets, retry policy, or the circuit breaker. It composes with any of the three cadence modes, not just all.

What is TTL?

One freshness clock per source, stamped on every successful run.

Each source's last success is written to cache_meta under a synthetic SCHEDULER ticker (unified:<source>). It stays fresh until its age passes ttl_hours, then it's stale and the next matching-mode run refreshes it.

0h — freshttl_hours — stalenext run — refreshed
gdelt / finnhub — 6h sec_filings — 12h most sources — 24h cftc / transcripts — 168h (7d)

Bootstrap flow

The dedicated cold-start command — python -m src.scheduler bootstrap [--source] [--since] [--resume].

  1. Universe snapshotrefresh ticker membership (NASDAQ-100, IVV, SEC) before anything else needs a ticker list.
  2. Per-source partitioned ingestioneach source's work splits into checkpointed partitions (SEC: one per calendar day) recorded in a resumable partition ledger, bounded to 30d SEC/market/news lookback, 5 macro observations.
  3. Budget-gated requestsevery partition reserves capacity against that source's per-minute/day/run RunBudget before any HTTP call.
  4. Normalizationraw provider payloads become typed records (ObservationRecord / NarrativeRecord / EventRecord).
  5. One committed revisionthe Store facade writes the SQLite ledger row, FTS5 lexical row, and Chroma embedding together, then stamps the source fresh in cache_meta.
  6. SEC filing text still waitsbootstrap's SEC partition is discovery-only, same as daily/hourly/all — parsing is weekly-only, no exceptions.
bootstrap seeds 17 of 23 sources through checkpointed partitions (universe, SEC discovery, market/news vendors, FRED, official feeds). Sources with their own incremental cursor — yfinance, sec_companyfacts, gdelt, earnings_transcripts, ir_pages, estimates — aren't in that list; ordinary daily/hourly/weekly runs catch those up instead. all --force is the simpler lever: re-run every registered source right now, ignoring TTLs, with no partitioning or resume.
